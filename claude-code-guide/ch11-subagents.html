11

Subagents と並列実行

コンテキストは有限資源です。サブエージェントは別のコンテキストウィンドウで働き、要約だけを返すことで、 メインの会話を汚さずに調査・検証・並列作業を可能にします。

原理との対応

サブエージェントは、図 1-1 の「オーケストレーション」を担う要素で、原理でいえば「分ける」の実装です（3-9 メモリ）。別のコンテキストで別のモデル呼び出しを回し、要約だけを親のコンテキストに戻します。親は毎ターンコンテキストを丸ごと送り直している（3-9 コンテキスト）ので、調査で読んだファイルが親に載らなければ、その分だけ以後の全ターンが安く速くなります。代償は、分離すると過程は見えなくなること——サブエージェントが途中で何を読み、何を試したかは親のコンテキストに残りません。なお tools で Write を拒否するような制約は、コンテキストではなくハーネス側で効く「ハーネスで強制する」（3-9 ガードレール）の一種です。廃れないのは「分けて要約だけ戻す」という構造とそのトレードオフで、変わるのは同時実行数や入れ子の深さの既定値、フロントマターの項目、組み込みエージェントの顔ぶれです。

11-1. コンテキスト分離の効果

  • コンテキスト保全：探索や実装をメイン会話から切り離す
  • 制約の強制：使えるツールを限定できる（読み取り専用の調査役など）
  • 設定の再利用：ユーザーレベルに置けば全プロジェクトで使える
  • 挙動の専門化：ドメイン特化のシステムプロンプトを与える
  • コスト制御：Haiku など高速・安価なモデルにタスクを回す

11-2. カスタムサブエージェントの定義

YAML フロントマター＋Markdown 本文（＝そのエージェントのシステムプロンプト）。

---
name: code-reviewer
description: 品質・セキュリティ観点でコードをレビューする。コード変更後に使用。
tools: Read, Glob, Grep
model: sonnet
---

あなたはコードレビュアーです。呼び出されたらコードを分析し、
品質・セキュリティ・ベストプラクティスについて具体的で実行可能な
フィードバックを提供してください。
場所スコープ優先度
管理設定組織全体1（最高）
--agents CLI フラグ（JSON）そのセッションのみ2
.claude/agents/プロジェクト3
~/.claude/agents/全プロジェクト4
プラグインの agents/プラグイン有効時5（最低）
運用メモ

v2.1.198 以降、/agents は作成ウィザードを開きません。Claude に「サブエージェントを作って」と頼むか、.claude/agents/ のファイルを直接編集します。ファイルの追加・編集は再起動なしで反映されます（新規ディレクトリ作成時を除く）。

試してみる：即席サブエージェントを定義 
claude --agents '{
  "reviewer": {
    "description": "読み取り専用のコードレビュー担当",
    "prompt": "あなたはシニアレビュアーです。品質とセキュリティに絞って指摘してください。",
    "tools": ["Read", "Grep", "Glob"],
    "model": "haiku"
  }
}'

起動後に「reviewer エージェントで src/ をレビューして」と依頼します。

11-4. サブエージェントの位置づけ

手段扱う範囲参照
サブエージェント（本章）1 セッション内の委譲ワーカー。独自コンテキストで作業し、要約を返す—
エージェントビュー／エージェントチーム／動的ワークフローセッションをまたぐ並列化6-7

並列化の手段をどう選ぶかは 6-7 で扱います。

コスト

並列セッション／サブエージェントを増やすとトークン消費も増えます。エージェントチームは各メンバーが独立した Claude インスタンスのため特に高コストです。

制限既定変更方法
同時実行数20。超えると Concurrent subagent limit reachedCLAUDE_CODE_MAX_CONCURRENT_SUBAGENTS（ultracode 有効時は非適用）
ネストの深さ3 階層（サブエージェントも自分のサブエージェントを生成できる）CLAUDE_CODE_MAX_SUBAGENT_SPAWN_DEPTH（1 で無効化）
セッション総数上限なし—
日本語版ドキュメントは古い

日本語版は「深さ 5・設定不可」としていますが、英語版は上表のとおり既定 3 階層・環境変数で変更可です。同時実行 20 の上限は日本語版に記載がありません。

試してみる：並列実行の状況を見る

セッション内で：

/tasks

実行中・完了したバックグラウンド作業が一覧され、選んで停止できます。

ターミナルで：

claude --worktree

隔離した git worktree で新しいセッションが始まります。--worktree は git リポジトリ内でのみ使え、作られた worktree は .claude/worktrees/ 配下に置かれて、変更がなければ自動で片付けられます。

11-5. 活用パターン

  • 調査の委譲：「サブエージェントを使って、認証のトークン更新の仕組みと再利用できる OAuth ユーティリティがあるか調べて」
  • 敵対的レビュー：実装後、新しいコンテキストのサブエージェントに差分だけを見せて欠落を報告させる。/code-review がこれを標準化したもの
  • ファンアウト：claude -p をループで回し、ファイル単位の移行を大量に並列処理（--allowedTools でツールを絞る）
レビュー結果の扱い

「欠落を探せ」と指示されたレビュアーは、健全な実装でも何かしら報告します。すべてを追うと過剰実装になるため、正確性か明示要件に関わるものだけを対応対象とし、残りは任意扱いにするのが公式の推奨です。

11-6. この章の持ち帰り

サブエージェントは「並列で速い」より、「メインを汚さない」ことが本体の価値です。

覚えること仕事での効き目具体的な操作
別のコンテキストで回し、要約だけを戻す親が安く速くなる理由と、「途中で何をしたか」を後から親に聞いても分からない理由が同じ原理から出る。過程が要る仕事は委譲しない、と判断できる3-9 メモリ、3-9 コンテキスト
調査は明示的に委譲する大量のファイル読みが親に載らないので、合計では安くなることが多い。本題の議論も濁らない「サブエージェントで◯◯を調べて」
Explore は軽い読み取り専用で CLAUDE.md も git status も読まない。探索の初手として最適組み込みの Explore
敵対的レビューを型にする実装の経緯を知らない相手に差分だけ見せる。見落としが出る/code-review がこれを標準化したもの
ファイルを作らずに試せるサブエージェント定義を書く前に、その場で挙動を確かめられるclaude --agents '{...}'
同じファイルを触るなら worktree で隔離並列セッションのファイル競合を防ぐ。変更が無ければ自動で片づくclaude --worktree
意外と知られていない

日本語版ドキュメントは、この章の数値が古いままです。ネストの深さを「5 階層・設定不可」としていますが、英語版では既定 3 階層・環境変数で変更可。同時実行 20 の上限に至っては日本語版に記載がありません。仕様で迷ったら英語版を見る、が安全です。もう一つ、「欠落を探せ」と指示されたレビュアーは健全な実装でも必ず何か報告します——全部追うと過剰実装になるので、正確性か明示要件に関わるものだけを対応対象にしてください。
