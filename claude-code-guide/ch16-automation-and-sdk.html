16

自動化・CI/CD・Agent SDK

対話の外へ出すと Claude Code は「開発者の道具」から「パイプラインの部品」になります。

原理との対応

この章は図 1-1（1-1）のインターフェースのうち非対話実行・CI/CD・Agent SDK（対話の外からプロンプトを渡す）と、運用と観測性（人手なしで回し続け、外から測る）の実装です。claude -p も GitHub Actions もルーチンも、動いているのは対話と同じエージェントループ（3-9 ループ）で、変わるのは「誰がコンテキストの先頭を渡すか」と「ガードレール（3-9 ガードレール）をどこに置くか」（--allowedTools・--bare）だけです。Agent SDK はそのループを自分のプログラムから回すもので、SDK の tools 定義はツール使用（3-9 ツール使用）そのもの——定義はコンテキストに入り、モデルは選ぶだけで、実行は SDK 側（ハーネス）で起きます。廃れないのは「対話が無くても核の 4 つ（LLM・コンテキストウィンドウ・ツール使用・エージェントループ）は同じで、人が周回の間に入れない無人実行では、ハーネス側の強制だけが頼りになる」という構造で、変わるのはフラグ名・連携先・SDK の API です。

16-1. 非対話モード

# 単発クエリ
claude -p "このプロジェクトの概要を説明して"

# スクリプト向けの構造化出力
claude -p "すべての API エンドポイントを列挙して" --output-format json

# ストリーミング
claude -p "このログを分析して" --output-format stream-json --verbose

# ツールを限定して無人実行
claude -p "Migrate $file from React to Vue." --allowedTools "Edit,Bash(git commit *)"
  • CI、pre-commit フック、バッチ処理に組み込める。パイプの入出力で他ツールと連結可能
  • 無人実行では --allowedTools や --permission-mode dontAsk で権限を絞るのが必須
  • CI では --bare を付ける。フック・スキル・カスタムコマンド・サブエージェント・プラグイン・MCP・自動メモリ・CLAUDE.md の自動検出をスキップし、マシンによらず同じ結果になる（公式の推奨モード。将来 -p の既定になる予定）。ただし OAuth・キーチェーンも読まないため、認証は ANTHROPIC_API_KEY（またはクラウドプロバイダの資格情報）が必要。--add-dir は部分的な例外で、その .claude/skills/ だけは読み込まれます
  • 出力を機械処理するなら --output-format json ＋ --json-schema で構造化出力を受け取れる
  • auto モードを -p と併用した場合（--permission-prompt-tool なし）、分類器が繰り返しブロックしてもそのアクションが実行されないだけで、実行自体は止まりません（日本語版ドキュメントは「セッションを中止」と古い記述のままです）
  • 実行はセッションを作るため、--resume で後から追跡できる（--no-session-persistence で無効化）

16-2. CI/CD と GitHub / GitLab 連携

運用上の注意

自動レビューは人間のレビューの前処理であって代替ではありません。マージ承認の責任は従来どおり作成者とレビュアーにあります（決めておくべき最低ラインは 15-8）。加えて、自動化で PR 数と CI 実行回数が増えるため、CI の実行時間・課金とレビューの滞留も併せて見積もってください。

16-3. 定期実行とイベント駆動

手段実行場所特徴
ルーチン（/schedule）Anthropic 管理インフラPC がオフでも動く。API 呼び出しや GitHub イベントでもトリガー可能
デスクトップ定期タスク自分のマシンローカルファイル・ツールに直接アクセスできる
/loop現在のセッション内プロンプトを繰り返す。間隔省略時は Claude が自分でペース配分
チャネルMCP サーバー経由CI 結果・チャット・監視イベントを実行中セッションに push
Monitor ツールセッション内バックグラウンドでログ・ファイル変更・WebSocket を監視して反応

用途例：朝の PR レビュー、夜間の CI 失敗分析、週次の依存関係監査、マージ後のドキュメント同期。

試してみる：セッション内でタスクを予約する 
2分後に、今の時刻を教えて       # 自然文で1回限りのタスクが登録されるスケジュール済みタスクを教えて   # 登録済みタスクが一覧される

登録時に Claude が発火時刻を確認してきます。/loop 10m <プロンプト> だと初回まで最長 10 分（さらにジッター）待つため、まずは 1 回限りで挙動を見るのが早いです。

止め方は登録方法で違います。自然文で頼んだタスクは Esc では消えず、「◯◯のタスクをキャンセルして」と削除を頼みます。/loop を間隔なしで起動した場合（Claude が自分でペースを決める）は、次の実行を待つ間に Esc で保留中の起床予定がクリアされます。/loop 10m のように固定間隔で回しているものは Esc では止まらず、自然文タスクと同じくキャンセルを頼むか 7 日の自動失効を待ちます。定期タスクは作成から 7 日で自動失効し、セッションを閉じても止まります。無人で回し続けたい場合はルーチンかデスクトップ定期タスクを使ってください。

16-4. Claude Agent SDK

Claude Code をライブラリとして使い、独自エージェントを構築するための SDK（TypeScript / Python）。オーケストレーション、ツールアクセス、権限を完全に制御できます。

領域できること
基本エージェントループ、ストリーミング入出力、セッション（continue / resume / fork）
Claude Code 資産の再利用CLAUDE.md、スキル、フック、プラグイン、サブエージェントを SDK 側に読み込む
ツールインプロセス MCP サーバーによるカスタムツール定義、外部 MCP 接続、ツール検索
出力JSON Schema / Zod / Pydantic による構造化出力
制御権限モード、承認フローとユーザー入力、フックによる介入、ファイルチェックポイント
運用コスト追跡、OpenTelemetry 可観測性、セッション永続化、ホスティング、マルチテナント分離

16-5. この章の持ち帰り

対話の外に出すときは、再現性と権限の 2 点を先に固めます。

覚えること仕事での効き目具体的な操作
無人実行は「人が周回の間に入らないループ」対話の外に出しても核の 4 つは同じ。人が Esc で止められない分、止める・制限するはハーネス側の強制（ツール制限・--bare・合否の自動判定）に寄せると設計できる3-9 ガードレール・3-9 ループ
CI では --bare を付けるフック・スキル・MCP・CLAUDE.md の自動検出をスキップし、マシンによらず同じ結果になる（公式推奨）ただし認証は ANTHROPIC_API_KEY が必要
無人実行は必ずツールを絞る権限モードだけに頼らない。事故ったときの被害範囲を先に決めておく--allowedTools / --permission-mode dontAsk
出力を機械処理するなら構造化するパースを正規表現でやらずに済み、パイプラインが壊れにくい--output-format json --json-schema
-p の実行も後から追えるCI で何が起きたかをセッションとして再開して調べられる--resume（--no-session-persistence で無効化）
自動レビューは前処理であって代替ではないマージ承認の責任は従来どおり。PR 数と CI 時間の増加も見積もる「差分を作成者が説明できること」を条件に
意外と知られていない

定期実行の止め方は、登録方法ごとに違います。自然文で頼んだタスクは Esc では消えず、「◯◯のタスクをキャンセルして」と頼む必要があります。/loop 10m のような固定間隔も Esc では止まりません（間隔なしの /loop だけは Esc で保留中の起床がクリアされます）。いずれも作成から 7 日で自動失効します。もう一つ、-p の非対話実行では信頼検証が無効になります——プロンプトインジェクション対策が 1 枚薄くなる点は、CI 設計で意識してください。
