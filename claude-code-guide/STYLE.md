# ドキュメントのフォーマットルール

`claude-code-guide/` の見た目に関する決まり。値はすべて `assets/style.css` の `:root` にトークンとして定義してあり、
**本文の HTML に色・サイズ・幅を直接書かない**。ここに無い見た目が欲しくなったら、まずトークンを増やしてから使う。

## 1. 色 — ユニバーサルデザインのカラーパレット

すべての文字色は、使われる背景に対して **WCAG 2.2 AA（通常文字 4.5:1 以上）** を満たす。下表の比は白背景 `#ffffff` に対する実測値で、
薄い背景（`--surface-2` `--accent-bg` `--code-bg`）でも 4.5 を切らないことを確認済み。

| トークン | 値 | 役割 | 白背景との比 |
|---|---|---|---|
| `--text` | `#1f1e1b` | 本文 | 16.7 |
| `--text-soft` | `#4d4a43` | 導入文・補足・カード本文 | 8.8 |
| `--muted` | `#66604f` | ラベル・図の説明・表の見出し・フッター | 6.3 |
| `--accent` | `#a3432a` | リンク・見出しの縦線・強調ラベル | 6.2 |
| `--ink` | `#2c3d4f` | 注記の縦線・図の枠 | 11.1 |
| `--ok` | `#3a6b3a` | コピー完了などの成功表示 | 6.3 |
| `--code-text` | `#37332c` | コード | 12.6 |

背景と線は次のとおり。文字を載せてよいのは `--bg` `--surface` `--surface-2` `--accent-bg` `--code-bg` `--ink-soft` の 6 つで、
どれも上の文字色すべてが AA を満たす。

| トークン | 値 | 用途 |
|---|---|---|
| `--bg` / `--surface` | `#ffffff` | ページ・カード・注記の地 |
| `--bg-alt` / `--surface-2` | `#f8f7f4` / `#f7f6f2` | サイドバー・表の見出し・Source ブロックの地 |
| `--accent-bg` / `--accent-soft` | `#fdf5f2` / `#edd8cf` | 「試してみる」の地と枠、ホバー |
| `--ink-soft` | `#eef3f7` | 図の中の淡い面 |
| `--code-bg` | `#f6f5f1` | コードの地 |
| `--line` / `--line-strong` | `#e7e4dc` / `#d2ccbe` | 罫線（文字は載せない） |

守ること

- **色だけで意味を伝えない。** 注意の注記は縦線を赤くするだけでなく `class="note warn"` にラベル文字を付ける。表の「上ほど高い」は見出し文で示す。
- 色相は橙赤（`--accent`）と藍（`--ink`）の 2 系統だけ。赤と緑を並べて区別に使わない（`--ok` は単独のアイコン表示にだけ使う）。
- 図（SVG）の中も同じトークンを `var(--…)` で参照する。固有色を持つのは表紙の概要図（`claude-code-overview/` 由来）だけ。

## 2. 文字 — フォントとサイズ

| トークン | 値 | 用途 |
|---|---|---|
| `--font-sans` | Hiragino Sans → BIZ UDPGothic → Noto Sans JP → Yu Gothic UI → Meiryo | 本文。Windows では UD フォントの BIZ UDPGothic が当たる |
| `--font-serif` | Hiragino Mincho ProN → Yu Mincho → Noto Serif JP | **表紙の大タイトルだけ**の装飾。章題・節見出し・章カード・サイドバーを含め、読むための文字はすべて `--font-sans` |
| `--font-mono` | ui-monospace → SF Mono → Menlo → Consolas | コード・ラベル・番号 |

サイズは 4 段。**12px 未満の文字は作らない。**

| トークン | 値 | 用途 |
|---|---|---|
| `--fs-lg` | 1.16rem（18.5px） | 節の見出し（h3） |
| `--fs-md` | 1rem（16px） | 本文・注記・箇条書き。行間 1.85 |
| `--fs-sm` | .875rem（14px） | 表・コード・カード本文・「試してみる」の補足・Source・サイドバー |
| `--fs-xs` | .75rem（12px） | ラベル（NOTE / SOURCE / 試してみる）・表の見出し・図の説明・フッター・パンくず。下限 |

- 本文と表以外で太字を使うのは、段落の要点 1 か所まで。文全体を太字にしない。
- 英数字と和文の間には半角スペースを入れる（`Claude Code の全体像`、`200 行以下`）。
- 見出しの中にタグを入れない（`check_docs.py` の検査条件でもある）。

## 3. 幅 — コンテンツ幅は 2 種類だけ

| トークン | 値 | 適用先 |
|---|---|---|
| `--measure` | 54rem（864px） | **章ページのすべての要素**。段落・箇条書き・表・図・コード・注記・カード・「試してみる」・Source・ページャ |
| `--measure-wide` | 64rem（1024px） | 表紙だけ。タイトル・概要図・章カード |

864px は本文 1 行が全角 54 字前後になる幅。散文の読みやすさの上限（40〜50 字）を少し超えるが、表と図が多い技術資料では 800〜900px が一般的で、こちらを優先した。

章ページでは `.chapter > *` に `max-width: var(--measure)` が一括で効くので、個別の要素に幅を書かない。
表が幅を超えるときは `.table-scroll` が横スクロールにする。図の SVG は枠いっぱいに広がる（`viewBox` で縮む）。

## 4. 部品の使い分け

| 部品 | クラス | 使うとき |
|---|---|---|
| 注記 | `div.note` | 本文の流れから外れる補足。`label` に短い見出しを付ける。注意喚起は `note warn` |
| 試してみる | `div.try` | 読者がその場で打てるコマンド。シェルとセッション内コマンドを 1 つのブロックに混ぜない |
| Source | `div.src` | 節の末尾に 1 つ。公式ドキュメントへのリンク |
| 図 | `figure` + インライン SVG | 「図 N-M：」で始まる `figcaption` を必ず付ける。番号は章ごとに 1 から |
| 表 | `div.table-scroll > table` | 3 列以上の比較。順序のある軸は上ほど高い／強い／深い |
| カード | `div.cards > div.card` | 2〜4 個の並列な要点。`tag` に短い見出し |

各章は「導入文 → 原理との対応（`note`） → 節 … → この章の持ち帰り（表 + 意外と知られていない `note`）」の順で揃える。
