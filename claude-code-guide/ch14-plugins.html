14

Plugins とマーケットプレイス

プラグインは「配布のための箱」です。スキル・サブエージェント・フック・MCP サーバーを 1 つのインストール単位にまとめます。

原理との対応

この章だけは、3-9 のどの原理の実装でもありません。図 1-1（1-1）では「拡張とオーケストレーション」の端にある、既にある部品を「まとめて配布・共有する単位」がプラグインです。新しい部品は増やさず、既にある部品をまとめて配る箱にすぎません。中身の各部品はそれぞれ別の原理に属します——スキルはコンテキストに足すもの、サブエージェントはコンテキストを分けるもの（3-9 メモリ）、フックはツール実行の直前にハーネスで割り込むもの（3-9 ガードレール）、MCP はツールの定義を増やすもの（3-9 ツール使用）。廃れないのは「箱を開けたら、中身がコンテキストに足されるものか、ハーネスで実行されるものかで読む」という見方で、変わるのは plugin.json のスキーマとマーケットプレイスのコマンド体系です。

14-1. スタンドアロン設定との使い分け

アプローチスキル名向いている場面
スタンドアロン（.claude/ 配下）/hello個人ワークフロー、プロジェクト固有の調整、試行錯誤
プラグイン（.claude-plugin/plugin.json を持つ自己完結ディレクトリ）/plugin-name:helloチーム共有、コミュニティ配布、バージョン管理、複数リポジトリでの再利用

.claude/ で素早く試作し、共有段階でプラグインに変換するのが定石です。

14-2. プラグインの構造

my-plugin/
├── .claude-plugin/
│   └── plugin.json     # name / description / version / author
├── skills/
│   └── review/SKILL.md # → /my-plugin:review
├── agents/             # サブエージェント定義
├── hooks/              # フック定義
└── .mcp.json           # 同梱する MCP サーバー
{
  "name": "my-first-plugin",
  "description": "A greeting plugin to learn the basics",
  "version": "1.0.0",
  "author": { "name": "Your Name" }
}
  • name はスキルの名前空間になる（衝突回避）
  • version を上げたときにユーザーへ更新が届く（省略時は git のコミット SHA 単位）
  • ローカル検証は claude --plugin-dir ./my-plugin。反映は /reload-plugins

14-3. インストールと配布

/plugin                                   # マーケットプレイスを参照
/plugin marketplace add anthropics/claude-plugins-official
/plugin install skill-creator@claude-plugins-official
/plugin list                              # 導入済みプラグイン一覧
  • マーケットプレイスは git リポジトリ等でホストでき、チーム内配布・社内標準の展開に使える
  • 依存バージョンの制約宣言、複数プラグインの一括インストール（バンドル）に対応
  • 組織向けに「この作業ならこのプラグイン」を提案する relevance ブロックも定義できる
  • コードインテリジェンスプラグイン（言語サーバー連携）は型付き言語で特に効果が大きい
  • セキュリティ系の公式プラグイン：security-guidance（自分の変更を自己レビュー）、Claude Security（脆弱性スキャン）
試してみる：公式マーケットプレイスを追加 
/plugin marketplace add anthropics/claude-plugins-official/plugin                # 一覧をブラウズしてインストール/plugin list           # 導入済みを確認

14-4. この章の持ち帰り

プラグインは「配布のための箱」。作るタイミングを間違えなければ管理コストは増えません。

覚えること仕事での効き目具体的な操作
プラグインは箱。新しい部品を増やさない導入前に「中身のどれがコンテキストに足されるもので、どれがハーネスで実行されるものか」で読める。スキルはコンテキストに足されるだけだが、フックと MCP サーバーはハーネス側——あなたの権限で実際に動く。読むべき優先順位がそこから決まる図 1-1（1-1）の「拡張とオーケストレーション」・9-1 の全体マップ
.claude/ で試作し、共有段階で箱にする最初からプラグインにすると試行錯誤が重い。2 つ目のリポジトリで必要になったときが転換点9-3 の導入トリガー
name が名前空間になるチームのスキル名が衝突しない。/my-plugin:review の形で呼べる.claude-plugin/plugin.json
version を上げると更新が届く配布したあとの改善を全員に反映できる。省略すると git の SHA 単位になるセマンティックバージョンを付ける
ローカル検証してから配る壊れたものを配らずに済むclaude --plugin-dir ./my-plugin → /reload-plugins
型付き言語ならコードインテリジェンスファイル全読みが定義ジャンプに置き換わる。速度とコストの両方に効く公式マーケットプレイスから導入
意外と知られていない

プラグイン由来のサブエージェントでは hooks / mcpServers / permissionMode が無視されます。セキュリティ上の制限で、必要なら定義を .claude/agents/ にコピーします。裏を返せば、他人のプラグインのスキルやフックは、あなたの権限で任意のコードを実行しうるということです。導入前に中身を読む習慣は、社内配布であっても持っておいてください。
