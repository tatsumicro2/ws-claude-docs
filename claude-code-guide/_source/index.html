0-3. スライド化のための構造ルール

この HTML は、別の AI に読み込ませてスライド（PowerPoint 等）へ変換することを前提に構造化しています。

  • <section class="chapter" id="chN" data-chapter="N"> = 章（＝セクション区切りスライド 1 枚に対応）
  • <article class="slide" data-slide="N-M" data-slide-title="…"> = スライド 1 枚の単位。data-slide-title がそのままスライドタイトルになります
  • 各スライド内は「リード文 → 箇条書き or 表 → 図 → 出典」の順で統一
  • .src ブロック＝そのスライドの出典。スライド脚注にそのまま転記できます
  • 図はすべてインライン SVG（外部画像依存なし）。PNG 化するか、図の内容を PowerPoint 図形で再現できます

変換を依頼するときのプロンプト例

この HTML を読み込み、data-slide 属性を持つ <article> を 1 スライドとして
PowerPoint を作成してください。
- 章（data-chapter）ごとにセクション区切りスライドを挿入
- スライドタイトルは data-slide-title の値
- 本文は箇条書きを維持し、1 スライド 6 行以内に圧縮
- 表は表オブジェクトに変換。ただし 8 行を超える表は分割し、分割できない一覧
  （8-2 フックイベント、17 章の用語集、6-4 フロントマター）は代表 5 行 ＋「全件は付録へ」とする
- 1 スライドの本文は全角 400 字を上限に圧縮する
- .src ブロックの内容はスライド下部の出典脚注へ
- 「v2.1.x 以降」などのバージョン条件は脚注として残す
01

Claude Code とは

まず全体像。Claude Code は「コード補完ツール」ではなく、コードベースを読み、ファイルを編集し、コマンドを実行する自律型エージェントです。

1-1. 定義 — agentic coding ツール

Claude Code は Anthropic の agentic コーディングツールです。コードベース全体を理解し、複数のファイルとツールをまたいで目標を達成します。

Read
コードベースを読む

ファイル検索・全文検索・依存関係の把握。現在開いているファイルだけを見るインライン補完とは異なる。

Write
ファイルを編集する

複数ファイルにまたがる協調的な編集。新規作成・リネーム・再編成まで行う。

Execute
コマンドを実行する

テスト、ビルド、git、パッケージマネージャ。コマンドラインでできることは基本的に実行できる。

Verify
結果を検証する

テスト実行やスクリーンショット比較で自分の作業を確認し、失敗すれば修正を繰り返す。

「認証のバグを直して」と依頼すると、関連ファイルの探索 → 複数ファイルの読み込み → 協調した編集 → テスト実行 → 必要ならコミット、という一連の流れを自律的に実行します。

1-5. 最初に知っておく料金と使用量

機能の話に入る前に、費用の感覚だけ押さえておきます（詳細は 13 章）。

  • Claude Code は会話するたびにトークンを消費します。読み込んだファイル、コマンド出力、思考もすべて対象です
  • 費用の出方は契約によって違います。サブスクリプション（Pro / Max / Team / Enterprise）は利用枠、Console（API）やクラウド経由は従量課金です
  • 今どれだけ使ったかは /usage（別名 /cost・/stats）で確認できます。Pro / Max は /usage-credits で月間の支出上限を設定できます
  • 高くつきやすいのは、Opus や max の努力レベル、エージェントチーム、/batch、回し続ける /loop。まずは既定の Sonnet ＋通常の使い方から始めるのが安全です
  • 意図せぬ課金を防ぐ最大の対策は、タスクごとに /clear してコンテキストを膨らませないことです（13-3）

02

コアメカニズム

Claude Code を「なんとなく賢いツール」から「挙動が予測できる道具」に変えるのが、この章です。 agentic ループ・モデル・ツール・コンテキストウィンドウ・セッションの 5 つが土台になります。

2-1. agentic ループ — 3 フェーズの反復

タスクを与えると、Claude は ①コンテキストの収集 → ②アクションの実行 → ③結果の検証 という 3 フェーズを、必要なだけ繰り返します。フェーズは厳密には分かれておらず、互いに溶け合います。

  • ループを駆動するのは 推論するモデル と 行動するツール の 2 要素。
  • Claude Code はモデルを取り巻く agentic ハーネス（ツール群・コンテキスト管理・実行環境）として機能します。
  • ユーザーもループの一部です。Esc で即停止、あるいは実行中に文章を送って軌道修正できます。
試してみる：ループを観察する 
claude "READMEを読んで、このプロジェクトのテスト実行方法を教えて"

実行中に Ctrl+O を押すと、思考とツール使用の詳細が展開されます。

2-5. コンテキストウィンドウとコンパクション

コンテキストウィンドウには、会話履歴・ファイル内容・コマンド出力・CLAUDE.md・自動メモリ・読み込まれたスキル・システム指示が同居します。ここが Claude Code 運用の最大の制約です。

コンテキストが埋まると

  • Claude Code は古いツール出力を整理し、必要なら会話を自動コンパクション（要約）します
  • 会話の早い段階で口頭で伝えた指示は失われる可能性がある → 恒久ルールは CLAUDE.md に書く
  • /context で内訳を確認、/compact「API 変更に注目して」 のように焦点を指定して手動圧縮できます
  • プロジェクトルートの CLAUDE.md はコンパクション後にディスクから再読み込みされます（ネストされた CLAUDE.md は再注入されない）

2-6. セッション・チェックポイント・巻き戻し

  • セッションは独立：新しいセッションは常に新しいコンテキストで始まる。橋渡しは CLAUDE.md と自動メモリが担う
  • 保存場所：会話は ~/.claude/projects/ 配下に JSONL で保存される
  • 再開：claude --continue（直近を継続）／ claude --resume（一覧から選択）／ /resume
  • フォーク：--fork-session や /branch で履歴を複製し、別 ID の会話として分岐
  • チェックポイント：プロンプトを送るたびに、その直前のコード状態が自動保存される（＝復元の単位はターン。1 ターン内の途中には戻れない）。/rewind、または入力欄が空の状態で Esc 2 回で、「会話だけ」「コードだけ」「両方」の復元と部分要約を選べる。保持は直近 100 件、セッション終了の 30 日後に自動削除
  • 名前付け：/rename でセッションに名前を付けるとワークストリーム管理が楽になる
  • worktree：同じリポジトリを別ディレクトリにもう一つチェックアウトする git の機能。claude --worktree で使うと、並列セッションが同じファイルを奪い合わずに済む（7-4）
重要な限界

チェックポイントは Claude が行ったファイル変更のみを追跡します。Bash コマンドや外部プロセスによる変更は対象外で、git の代替にはなりません。DB や API、デプロイなど外部副作用も巻き戻せません（だからこそ実行前に確認が入ります）。

3-4. 権限モード — 6 つのベースライン

Shift+Tab が巡回するのは default（Manual）→ acceptEdits → plan の 3 つです。auto はアカウントが利用条件を満たすときだけ、bypassPermissions は有効化フラグ付きで起動したときだけサイクルに加わり、dontAsk はサイクルに現れず --permission-mode dontAsk でのみ設定します。モードは「ベースライン」で、この上に個別の許可／確認／拒否ルールを重ねます。

モード確認なしで実行されるもの最適な用途
default（UI 表記：Manual）読み取りのみ導入初期、機密性の高い作業
acceptEdits読み取り＋ファイル編集＋一般的な FS コマンド（mkdir/mv/cp 等）レビューしながらの反復開発
plan読み取りのみ（編集せず計画を提案）変更前の調査・設計
autoすべて。ただしバックグラウンドの安全チェック（分類器）付き長時間の自律タスク
dontAsk事前承認済みツールのみロックダウンした CI / スクリプト
bypassPermissionsすべて（チェックなし）⚠ 隔離コンテナ・VM のみ
  • bypassPermissions 以外では、保護されたパス（リポジトリ状態や Claude 自身の設定）への書き込みは自動承認されません。
  • 拒否ルール・確認ルールは bypassPermissions を含むすべてのモードで有効です。
  • 既定モードは設定の permissions.defaultMode で固定できます。

06

Skills（スキル）

スキルは最も柔軟な拡張手段です。実体は SKILL.md という Markdown ファイル 1 枚。 Claude が自動で読み込むことも、/名前 であなたが呼び出すこともできます。

6-1. スキルとは何か

  • ディレクトリに SKILL.md を置くだけで、Claude のツールキットに手順・知識が追加される
  • 本文は使用時にしか読み込まれないため、長い参照資料でも普段はほぼ無コスト
  • カスタムコマンド（.claude/commands/*.md）はスキルに統合済み。両者とも /deploy として動作するが、スキルの方が高機能（補助ファイル、呼び出し制御、自動発火）
  • Claude Code のスキルは Agent Skills オープン標準に準拠。他の AI ツールとも互換性がある

作成する目安

同じプレイブック・チェックリスト・複数ステップの手順を繰り返し貼り付けているとき、または CLAUDE.md の一節が「事実」ではなく「手順」に育ってきたとき。

6-6. スキルのライフサイクルと評価

  • 呼び出されたスキルの本文は会話に 1 メッセージとして入り、セッション中ずっと残ります。単発の手順ではなく「常時適用される指示」として書くのが正解

  • 効果が薄れたように見えるときは、description と指示を強化するか、コンパクション後に再呼び出しします

コンテキストは有限資源です。サブエージェントは別のコンテキストウィンドウで働き、要約だけを返すことで、 メインの会話を汚さずに調査・検証・並列作業を可能にします。

  • 入力：イベントの JSON コンテキストが stdin（コマンドフック）または POST ボディ（HTTP フック）で渡される。編集対象のパスを受け取る環境変数は用意されていないので、jq -r '.tool_input.file_path' のように stdin の JSON から取り出す（環境変数で渡るのは CLAUDE_PROJECT_DIR などに限られる）
  • 出力その 1（終了コード）：exit 0 = 通過、exit 2 = ブロックし、stderr の内容が Claude へのフィードバックになる
  • 出力その 2（構造化 JSON）：exit 0 ＋ JSON で決定を細かく制御。exit 2 と JSON の併用は不可（exit 2 のとき JSON は無視される）
  • フックの種類：コマンド／HTTP／プロンプトベース（LLM に判定させる）／エージェントベース（実験的）
#!/bin/bash
# PreToolUse: 危険な SQL をブロックする例
INPUT=$(cat)                                            # stdin の JSON を受け取る
COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command')  # 実行されようとしているコマンド
if echo "$COMMAND" | grep -q "DROP TABLE"; then
  echo "Blocked: dropping tables is not allowed" >&2    # stderr が Claude へのフィードバック
  exit 2                                                # exit 2 = ブロック
fi
exit 0

MCP 連携（Model Context Protocol）

MCP は AI ツールを外部データソースに接続するためのオープン標準です。 これにより Claude Code は、DB のクエリ、Jira の更新、Slack からのデータ取得、ブラウザ操作などを行えます。

9-1. MCP の位置づけ

  • MCP が与えるもの＝外部システムと相互作用する能力（ツールとデータアクセス）
  • Skill が与えるもの＝その能力を効果的に使う知識（スキーマ、クエリパターン、社内ルール）
  • 両者はセットで使う。例：MCP が DB に接続し、Skill がデータモデルと典型クエリを教える

接続前の注意

信頼の確認

外部コンテンツを取得するサーバーはプロンプトインジェクションのリスクにさらされます。自作するか、信頼できる提供元のサーバーのみを使ってください。Anthropic はディレクトリ掲載時に基準審査を行いますが、MCP サーバーのセキュリティ監査・管理は行いません。

11-3. 権限ルールの書き方

ルールは Tool または Tool(specifier) の形式。評価順は deny → ask → allow で、最初にマッチしたものが結果を決めます（ルールの詳細度は順序を変えません）。

{
  "permissions": {
    "allow": [
      "Bash(npm run test:*)",
      "Read(./src/**)",
      "Skill(commit)"
    ],
    "ask": [
      "Bash(git push:*)"
    ],
    "deny": [
      "Bash(rm -rf *)",
      "Read(./.env)",
      "WebFetch(domain:internal.example.com)"
    ],
    "defaultMode": "acceptEdits"
  }
}
書き方意味
Bashすべての Bash 呼び出し。deny に書くとツール自体が Claude から見えなくなる
Bash(npm run build)コマンド完全一致
Bash(aws *)ワイルドカード（* は任意位置に置ける）
Read(./.env) / Edit(src/**)パス指定
WebFetch(domain:example.com)ドメイン指定
mcp__github / mcp__github__create_issueMCP サーバー単位／ツール単位
Skill(name) / Skill(name *)スキルの完全一致／前方一致
Agent(model:opus)入力パラメータでのマッチ（deny / ask のみ）
落とし穴

広い deny ルールは、より狭い allow ルールより常に優先します。Bash(aws *) を deny しつつ Bash(aws s3 ls) だけ allow する、という書き方はできません。また Bash(command:rm *) のようなパラメータ指定は複合コマンドで回避可能なため無視され、起動時に警告が出ます（正しくは Bash(rm *)）。

試してみる：権限ルールを1つ足す

権限は /permissions から足すのが安全です（8-3 でフックを書いた .claude/settings.local.json を、コピペで上書きして壊さずに済みます）。手で書く場合は同じファイルの permissions キーに追記してください。

11-4. 作業ディレクトリ境界とサンドボックス

  • 境界：Claude が書き込めるのは起動ディレクトリとそのサブディレクトリ。範囲外の読み取りは承認プロンプトの後に可能
  • 追加ディレクトリ：--add-dir / /add-dir で拡張。設定は原則読み込まれないが、例外が4つある — .claude/skills/、.claude/agents/、設定の enabledPlugins と extraKnownMarketplaces キー、そして CLAUDE_CODE_ADDITIONAL_DIRECTORIES_CLAUDE_MD=1 を設定したときの CLAUDE.md / rules。なお設定ファイルの permissions.additionalDirectories で追加した場合は例外が一切適用されず、ファイルアクセスのみ
  • サンドボックス化された Bash：/sandbox で有効化。ファイルシステムとネットワークを分離し、権限プロンプトを減らしつつ安全に自律実行させる
  • より強い分離が必要なら dev container、Docker、VM、あるいはクラウドセッション（隔離 VM）を使う

組み込みの保護

  • 読み取り専用コマンド（ls、cat、git status 等）はプロンプトなしで実行される
  • curl / wget のようなネットワーク取得コマンドは自動承認されない
  • コマンドインジェクション検出：疑わしい Bash は許可済みでも手動承認が必要になる
  • フェイルクローズド：マッチしないコマンドは既定で手動承認
  • WebFetch は別コンテキストウィンドウで処理し、プロンプトインジェクションの波及を抑える
  • 認証情報は macOS Keychain 等に安全に保存される

対話の外へ出すと Claude Code は「開発者の道具」から「パイプラインの部品」になります。

12-1. 非対話モード（headless）

# 単発クエリ
claude -p "このプロジェクトの概要を説明して"

# スクリプト向けの構造化出力
claude -p "すべての API エンドポイントを列挙して" --output-format json

# ストリーミング
claude -p "このログを分析して" --output-format stream-json --verbose

# ツールを限定して無人実行
claude -p "Migrate $file from React to Vue." --allowedTools "Edit,Bash(git commit *)"
  • CI、pre-commit フック、バッチ処理に組み込める。パイプの入出力で他ツールと連結可能
  • 無人実行では --allowedTools や --permission-mode dontAsk で権限を絞るのが必須
  • auto モードを -p と併用した場合、分類器が繰り返しブロックするとフォールバック先の人間がいないため中止される
  • 実行はセッションを作るため、--resume で後から追跡できる（--no-session-persistence で無効化）

14-3. 対話の技法

  • 会話として扱う：完璧なプロンプトは不要。まず投げて、そこから修正する

14-4. セッション管理とスケール

管理

  • 早めに軌道修正する。同じ問題で 2 回修正したらコンテキストは汚れている→ /clear して学びを織り込んだプロンプトで再スタート

  • 危険な試行はチェックポイント前提で。ダメなら /rewind
  • セッションに /rename で名前を付け、ワークストリームごとに使い分ける

スケール

  • 非対話モードで CI・スクリプトに組み込む

  • 大量ファイルはループ＋claude -p でファンアウト（まず 2〜3 件で検証してから全件）
  • 長時間の自律実行には auto モード＋敵対的レビューを組み合わせる
