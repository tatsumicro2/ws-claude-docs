# Claude Code 体系的入門

Claude Code の基礎を、Anthropic 公式ドキュメント（`code.claude.com/docs/ja`）を一次情報源として整理した学習資料。
**全 6 章 / 46 節**。日々の使い方に直結する範囲（概要と操作・指示の与え方・エージェントループとハーネス・セッション・ガードレール・コンテキスト管理とコスト）に絞り、
サブエージェント・MCP・プラグイン・CI/CD・Agent SDK は扱わない。

`index.html` をブラウザで開くと読める（外部依存なし）。

## 構成

```
claude-code-guide/
├── index.html              トップページ（章インデックス）
├── ch01-overview-setup-basics.html … ch06-context-cost-caching.html    章ごとのページ（1 ページ＝1 章）
├── site.json               資料名とフッター文言（章・節の構成は各章ファイルが唯一のソース）
├── assets/
│   ├── style.css           本文デザイン。色・文字・幅のトークンは :root にまとめてある（STYLE.md）
│   ├── app.js              コードブロックのコピー機能（同上）
│   ├── nav.css             サイドバー・ページャ・章カードのスタイル
│   ├── nav.js              目次・ページャ・章カード・フッターを toc.js から描画。開閉・スクロール位置の維持・節のハイライト
│   └── toc.js              生成物。全章の章・節一覧（build_toc.py が各章ファイルから抽出）
├── STYLE.md                見た目の決まり（カラーパレット・文字・幅・部品の使い分け）
├── tools/                  ビルドと検証のスクリプト（Python 3 標準ライブラリのみ）
├── dist/claude-code-guide.html   全章を 1 枚に結合した配布用 HTML（build_single.py の生成物。手で編集しない）
└── _todo/                  追加コンテンツの候補・レビュー結果・旧版などの作業メモ（資料の一部ではない。README に一覧）
    └── archive-19ch-2026-09-09/   6 章に再構成する前の全 19 章版と、その構成専用のスクリプト
```

スクリプトは**リポジトリ直下で** `python3 claude-code-guide/tools/<名前>.py` として実行する（どこから実行しても動くが、表記はこれに揃える）。

ドキュメントは **2 階層**（章 → 節）。左サイドバーには常に全 6 章が並び、
現在の章はその節まで展開される。他の章は見出し右の `›` で開閉できる。

## 章の並び

社内勉強会（週 1 回・10 分）で順に扱うことを前提に、**認知負荷の小さい順・実務で早く効く順**に並べている。
体系上の分類順ではない。

| 章 | 主題 | ねらい |
|---|---|---|
| 1 | 概要・セットアップ・基本操作 | 全体像を 1 枚の図で渡し、その日から使える操作を揃える |
| 2 | スキル・プロンプト・ルール | 「何をどう伝えるか」。CLAUDE.md・ルール・スキル・プロンプトの使い分け |
| 3 | エージェントループとハーネス | 中身の仕組みと、製品が変わっても残る原理（3-6） |
| 4 | セッションとチェックポイント | 会話の保存・再開・分岐と、戻せる範囲 |
| 5 | ガードレール機能 | 権限モード・権限ルール・サンドボックス・フック・管理設定 |
| 6 | コンテキスト管理・コスト・プロンプトキャッシュ | 速く安く動かすための、コンテキストの扱い方 |

2026-09-09 に全 19 章 / 112 節から 6 章に再構成した。旧版は `_todo/archive-19ch-2026-09-09/` にある。

### 設計意図と範囲

- 6 章の主題は固定。**サブエージェント・MCP・プラグイン・CI/CD・Agent SDK は扱わない。** 追加提案があっても、6 章の主題に入らないものは断る
  （候補の受け皿は `_todo/README.md` の「追加コンテンツの候補」）。
- 読者は社内勉強会（週 1 回・10 分）の参加者。並びは体系上の分類順ではなく、認知負荷の小さい順・実務で早く効く順。
  ただし「第 N 週 = 第 N 章」という対応付けは**しない**（本文に書かない）。
- 各章は「導入文 → 原理との対応（3-6 のどの原理の実装かを書く注記） → 節 … → この章の持ち帰り」の順。
  「持ち帰り」は**実務での効き目と、意外と知られていない事実**を書く枠で、章を追加したときは同じ体裁で用意する。

## 編集の仕方

### 原則 — 1 章 1 ファイルで完結

章ページには**その章の本文だけ**があります。左サイドバー・前後の章リンク・フッターは、`assets/toc.js` の
データから `nav.js` が表示時に組み立てます。だから **1 つの章を節構成ごと書き換えても、他の章ファイルは 1 バイトも変わりません**。
複数人で別々の章を同時に編集しても、コンフリクトするのは生成物（`assets/toc.js`・`dist/`）だけで、それは再生成すれば解決します。

### 本文を直すとき

該当する `chNN-*.html` を直接編集し、`build_toc.py` → `check_docs.py` → `build_single.py` を回す。

### 節を追加・改題したとき

1. 章ページに `<article class="slide" id="sN-M" data-slide="N-M" data-slide-title="…">` を追加する。
   節の id は `sN-1`, `sN-2`, … の連番にする（途中に入れたら後ろを付け替える）
2. `python3 claude-code-guide/tools/build_toc.py` を実行する。目次は章ファイルから自動で拾われる

### 章を追加したとき

1. 既存の章 HTML をコピーして `chNN-<slug>.html` を作り、`<section class="chapter" id="chN" data-chapter="N">`・`<h1>`・
   `.chapter-lede`・節 id を付け替えて本文を差し替える。ファイル名の番号順が章の並びになる
2. **末尾に「この章の持ち帰り」節、冒頭に「原理との対応」注記を用意する**（全章に揃えてある）
3. `python3 claude-code-guide/tools/build_toc.py` を実行する

### 編集を終える前に

```bash
python3 claude-code-guide/tools/check_docs.py    # OK が出るまで終えない
python3 claude-code-guide/tools/build_single.py  # 本文を変えたら dist/ を作り直す
```

### `check_docs.py` が通らなくなる書き方

| 規則 | 理由 |
|---|---|
| `data-slide-title="X"` と `<h3>N-M. X</h3>` の X を完全一致させる | 突き合わせ検査がある |
| `<h3>` の中にタグを入れない（`<strong>` も不可） | 検査が `[^<]+` で読む |
| `data-slide="N-M"` と `<h3>N-M.` の番号を一致させる | 同上 |
| 節の `id` は `sN-1` `sN-2` … の連番。N はファイル名の番号 = `data-chapter` | 章ファイルの宣言を突き合わせる |
| `assets/toc.js` を最新にする（`build_toc.py`） | 章ファイルから作り直した内容と比較する |

### 章番号を付け替えるとき

`tools/renumber_chapter.py` を、1 章ずつ、大きい番号から順に実行する。節 ID・図番号・章をまたぐリンク・アンカー・
数字だけのリンク文字列は一括で追随するが、**本文中の素の番号（「詳細は 6 章」「3-6 の原理」など）は拾えない**ので、実行後に手で確認する。

### 書き方の方針

- **出典は公式ドキュメント。日本語版が英語版より古い箇所は英語版に従い、その旨を注記する。** コミュニティ資料は事例収集にのみ使い、仕様の根拠にしない。
- バージョン依存の記述には `v2.1.x 以降` のように条件を添える。
- 表で順序のある軸（性能・コスト・優先度・容量）を扱うときは、**上ほど高い／強い／深い**で統一する。
- 「試してみる」ブロックは、シェルコマンドとセッション内コマンドを混ぜない。
- 数値や仕様を書くときは、可能なら手元で実測してから書く。推測で数字を置かない。
- 色・文字サイズ・幅は `assets/style.css` のトークンだけを使う。HTML に `style=` で直書きしない（[STYLE.md](STYLE.md)）。
- 英数字と和文の間には半角スペースを入れる。

### 共有ファイル

`index.html`（表紙）・`site.json`（資料名・フッター文言）・`assets/style.css` `nav.css` `nav.js` は全章に効く共有ファイルです。
編集は最小限にし、章の作業とは別の PR にしてください。`index.html` の `<!-- OVERVIEW:START -->` 区間は
`claude-code-overview/` の図を `build_toc.py` が差し込む自動生成区間です。

## ツール

| スクリプト | 用途 |
|---|---|
| `tools/build_toc.py` | 各章ファイルから目次データ `assets/toc.js` を生成し、トップページに `claude-code-overview/` の概要図を差し込む（冪等） |
| `tools/guide_toc.py` | 章ファイルの読み取りと目次の描画を共通化したモジュール（`build_toc.py` `build_single.py` `check_docs.py` が使う） |
| `tools/check_docs.py` | 内部リンク・アンカー・タグの対応・見出し番号・節 id の連番・`toc.js` の鮮度を検証。**編集後は必ず通す** |
| `tools/renumber_chapter.py` | 章番号を 1 つだけ付け替える（ファイル名・id・見出し・参照リンクを一括更新）。大きい番号から順に実行する |
| `tools/build_single.py` | 全章を 1 枚の自己完結 HTML（CSS / JS 埋め込み、章間リンクはページ内アンカー）に結合して `dist/claude-code-guide.html` に出力する。配布・印刷用 |

19 章版でだけ使った一括スクリプト（`split_guide.py` `add_takeaways.py` `reorder_chapters.py`）は
`_todo/archive-19ch-2026-09-09/tools/` に記録として残してある。
