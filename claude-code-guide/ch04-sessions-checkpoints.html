セッションとチェックポイント

セッションの状態はコンテキストウィンドウの中身だけで、閉じれば消えます。それを保存・再開・分岐する仕組みがセッション、ターン単位で作業状態を戻す仕組みがチェックポイントです。どこまで戻せて、どこから戻せないかを知ると、任せられる作業の大きさが変わります。

原理との対応

この章は図 1-1 の長期メモリのうち「会話そのもの」を保存する部分と、ガードレールのうち「戻す」部分の実装です。根拠は 3-6 コンテキスト（中身は JSONL としてディスクにあり、「覚えている」の正体はそれを読み直していること）と 3-6 ガードレール（巻き戻せるのはハーネスが自分で触ったものだけ）、そして 3-6 メモリ の「捨てる」「分ける」です。廃れないのは「セッションは互いに独立で、橋渡しは永続化だけ」「戻せるのはハーネスが触った範囲だけ」の 2 つで、保存件数・保持日数・コマンド名は変わります。

4-1. セッションの保存・再開・分岐

セッションはディレクトリに紐づく 1 つの会話です。会話は 1 行 1 イベントの JSONL として ~/.claude/projects/ に保存され、再開するときはこれを読み直してコンテキストを組み立て直します。新しいセッションは常に空のコンテキストで始まり、前のセッションから引き継がれるのは CLAUDE.md と自動メモリ（2 章）だけです。

したいこと操作挙動・制約
直前のセッションを続けるclaude --continueこのディレクトリの最新セッションを再開
過去のセッションを選んで続けるclaude --resume / セッション内で /resume一覧から選択。--from-pr で PR に紐づくセッションを指定できる
名前を付けて見つけやすくする/rename <名前> / claude --name複数の作業を並行するときに一覧で見分けられる
分岐して別の案を試す/branch / claude --fork-session履歴を複製し、別 ID の会話として分岐。元のセッションは変わらない
会話を書き出す/exportトランスクリプトをファイルに保存
会話を要約して確認する/recap再開直後に「どこまでやったか」を短く出す
再開の 2 択（Pro / Max）

約 1 時間以上放置した 10 万トークン超のセッションを再開すると選択ダイアログが出ます。「要約から再開」は即座に /compact 相当を行って以降を軽くする代わりに詳細が落ち、「そのまま再開」は全履歴を再処理・再キャッシュします。長い中断の後はプロンプトキャッシュが切れているため、どちらでも最初の 1 ターンが最も高くつきます（6-3）。

試してみる：再開と名前付け

ターミナルで直前のセッションを再開し：

claude --continue

開いたセッションの中で：

/rename oauth-work    # セッションに名前を付ける/recap                # ここまでの要約を出す

4-2. チェックポイントと巻き戻し

チェックポイントは、プロンプトを送るたびに直前のコード状態を自動保存する仕組みです。復元の単位はターン（3-1）で、git とは別物です。

項目内容
開く/rewind、または入力欄が空の状態で Esc 2 回（文字が残っていると入力のクリアになる）
戻せるもの「会話だけ」「コードだけ」「両方」を選べる。会話だけ戻して別の指示をやり直す、という使い方が多い
保持直近 100 件。セッション終了 30 日後に自動削除
コスト/rewind はプロンプトキャッシュを壊さない（6-3）
重要な限界 — git の代わりにはならない

追跡されるのはメイン会話がファイル編集ツール（Edit / Write）で行った変更だけです。次のものは巻き戻せません。

  • Bash コマンドや外部プロセスによる変更（sed -i、npm install、生成スクリプトなど）
  • サブエージェントの編集。バックグラウンドで走るフォークスキルや /code-review --fix も同様
  • DB・API・デプロイなど外部の副作用。だからこそ実行前に確認が入る（5 章）
  • シンボリックリンク・ハードリンクのパス（Restored the code, but skipped N files の警告が出る）

「/rewind があるから大丈夫」という前提で作業を任せるのが、最も危ない誤解です。戻したい状態は git でコミットしておきます。

試してみる：巻き戻す 
/rewind               # 会話・コードを巻き戻す（Esc 2 回でも可）

「会話だけ」を選び、同じ状態から別の指示を出し直してみてください。コードはそのまま、やり取りだけが戻ります。

4-3. セッションを区切る・並列にする

区切る

原則はひとつ、同じ問題で 2 回修正したらコンテキストは汚れている。失敗案が積み上がったコンテキストは、そのまま続けても精度が上がりません。/clear して、学んだことを織り込んだプロンプトで再スタートします。

操作何が起きるか使いどころ
/clearコンテキストを空にする。要約を生成しないので実質コスト 0。CLAUDE.md と自動メモリは次のターンで読み直されるタスクの切れ目、無関係な話題に移るとき、2 回失敗したとき
/compact <focus>会話を要約に置き換える。損失がある。focus で残したいことを指示できる継続が必要で、コンテキストが埋まりかけているとき（詳細は 6-6）
/rename → 新セッション今の会話に名前を付けて残し、別セッションを開く戻ってくる予定があるとき

大きめの機能は、Claude にインタビューさせて仕様を SPEC.md に落とし、新しいセッションで実装させると、設計の議論で汚れたコンテキストを実装に持ち込まずに済みます（2-5）。

並列にする

  • worktree で隔離する：claude --worktree は同じリポジトリを別ディレクトリにもう一つチェックアウトして起動し、並列セッションのファイル競合を防ぐ。同じファイルを触る作業を並走させるなら必須
  • Writer と Reviewer を分ける：実装したセッションとは別のセッション（または /code-review）に差分だけを見せると、実装に至った思考を知らないぶん確証バイアスが入りにくい
  • デスクトップ・クラウドの並列セッション：Desktop アプリは Git 分離した並列セッションを画面で管理でき、Web（claude.ai/code）は長時間タスクを手元のマシンから切り離せる（1-6）
worktree はキャッシュも分ける

プロンプトキャッシュは実質的にディレクトリ単位です。worktree はディレクトリが別なので、互いのキャッシュを読みません（6-3）。隔離の代償として、それぞれが自分のキャッシュを温め直します。

試してみる：隔離した worktree で起動する 
claude --worktree     # 別ディレクトリにチェックアウトして起動

元のディレクトリで動いているセッションと同時に、別ブランチの作業を任せられます。

4-4. 実行中のセッションを確認する

バックグラウンドや並列で動かし始めると「今どれが動いているのか」が分からなくなります。確認コマンドは対象ごとに違います。

対象コマンド見えるもの
このセッションのバックグラウンド処理/tasks長いコマンド（3-5）や Ctrl+B で裏に送ったタスクの一覧。確認・アタッチ・停止できる
バックグラウンドセッション全体ターミナルで claude agentsエージェントビュー。全セッションの状態と、どれが入力待ちかが 1 画面に出る
デスクトップの並列セッションDesktop アプリセッション画面で一覧
紛らわしい 2 つ

claude agents（エージェントビューを開く）と /agents は別物です。v2.1.198 以降、/agents はサブエージェント定義ファイルの場所を表示するだけになりました。

ステータスライン — 常に見えている計器

/context や /usage は「見に行く」ものですが、ステータスラインは常に見えている点が違います。コンテキスト残量やキャッシュの温度を横目で把握できると、/clear や /compact の判断が早くなります。

スクリプトが受け取れるフィールド中身注意
context_window.used_percentageコンテキスト使用率入力トークンだけから算出
current_usage入力・出力・キャッシュ書き込み・読み出しの内訳最初の API 呼び出し前と /compact 直後は null
prompt_cachehit_ratio / warm / ttl / misses短い表示なら warm と hit_ratio の 2 つで足りる（v2.1.251 以降）
その他git の状態、モデル名、レート制限、セッションのコストと経過時間—
試してみる：動いているものを見る・計器を作る 
/tasks/statusline モデル名とコンテキスト使用率をプログレスバー付きで表示して

/statusline は自然言語で頼むとスクリプトが ~/.claude/ に生成され、設定も自動で更新されます。

4-5. この章の持ち帰り

セッションの扱いで差が付くのは、「戻せる範囲」と「区切るタイミング」の 2 点です。

覚えること仕事での効き目具体的な操作
セッションは互いに独立。橋渡しは CLAUDE.md と自動メモリだけ「前のセッションで言ったのに」が通じない理由が分かる。残したいことは会話ではなくファイルに置く3-6 メモリ、2 章
チェックポイントは git の代わりにならないBash 経由・サブエージェント・外部副作用は戻せない。任せる前にコミットする習慣が事故を防ぐgit commit してから任せる
同じ問題で 2 回失敗したら /clear作り直すほうが速い。/clear は要約を生成しないので実質コスト 0/clear → 学んだことを織り込んで再依頼
戻る予定があるなら先に /rename--resume の一覧で見分けられる。複数の作業を並行しても迷子にならない/rename oauth-work
同じファイルを触る並列作業は worktree で隔離ファイル競合が消える。ただしキャッシュも別になるclaude --worktree
放置したバックグラウンドは /tasks で止める裏に回った長いコマンドは消費し続ける。入力待ちで止まっているセッションは claude agents で見つかる/tasks / claude agents
意外と知られていない

Esc 2 回が巻き戻しになるのは、入力欄が空のときだけです。もう一つ、ステータスラインは自然言語で作れます。「/statusline モデル名と使用率をバーで表示して」と頼めばスクリプトごと生成され、コンテキスト残量が常に見えるようになります。/clear の判断が早くなり、自動コンパクションがタスクの最中に走る事故が減ります。
