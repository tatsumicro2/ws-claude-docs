09

拡張レイヤーの全体像

Skills、Subagents、Hooks、MCP、Plugins。名前が似ていて混同しやすいので、 「いつ読み込まれるか」「誰が実行するか」という軸で整理します。ここが本資料の中核です。

原理との対応

この章は図 1-1（1-1）の「拡張とオーケストレーション」の全体像です。個々の拡張は核となる 4 つ（LLM・コンテキストウィンドウ・ツール使用・エージェントループ）のどこに効くかで分けられ、要するにコンテキストに足すか、ハーネスで割り込むかの 2 種類です。CLAUDE.md・rules・Skills はコンテキストに指示を足すもので、「文脈で頼む」側（確率的）です（3-9 ガードレール）。Subagents・Agent teams はコンテキストを分けて要約だけ戻す「分ける」の実装（3-9 メモリ）。Hooks と権限はモデルを介さずハーネスが動かす「ハーネスで強制する」側（決定論的）です（同じく 3-9 ガードレール）。MCP は「ツールの定義はコンテキストに入る」そのもので（3-9 ツール使用）、ハーネスが実行できる操作を増やしつつ定義分のコンテキストを消費します。Plugins はこれらを配る箱で、新しい要素は増やしません。廃れないのはこの分類と「コンテキストに載るものは毎ターン課金される」という構造で、変わるのは個々の機能名・遅延ロードや優先順位の細則です。

毎回確認せずに必ず実行してほしい処理があるHook を書く
2 つ目のリポジトリで同じ設定が必要になったPlugin としてパッケージ化

9-4. 機能ペアの比較

迷いやすい 4 組は、決め手の 1 問で切り分けられます。

迷うペア決め手（この 1 問で決まる）どちらを選ぶか
Skill / Subagentコンテキストを分けたいか分けない＝Skill（メインウィンドウに載る。参照資料・呼び出せる手順向き）
分ける＝Subagent（別ウィンドウ。要約だけが返る。大量読み込み・並列作業向き）
CLAUDE.md / rules / Skillいつ読ませたいか常時＝CLAUDE.md（中核規約）
該当ファイルを触った時＝rules（paths で絞る）
呼んだ時＝Skill（時々必要な資料・手順）
Hook / Skill保証が要るか必ず走らせる＝Hook（決定論的。コンテキストコストは原則ゼロ）
判断させる＝Skill（Claude が解釈するので結果は状況で変わる）
「.env を編集しない」のようなガードレールは指示ではなく PreToolUse フックにする＝お願いではなく強制
Subagent / Agent team作業者どうしが話す必要があるか不要＝Subagent（呼び出し元にだけ返す。低コスト）
必要＝Agent team（直接メッセージと共有タスクリスト。高コスト・実験的で既定は無効）

9-5. 機能別のコンテキストコスト

表の「コスト」は、コンテキストは毎ターン丸ごと送られるという 3-9 コンテキスト の原理から来ています。常駐するものは固定費、使うときだけ読むものは変動費、ハーネス側で動くもの（Hooks）は原則ゼロです。

機能読み込みタイミング読み込まれる内容コスト
CLAUDE.mdセッション開始全文毎リクエストに発生
Skills開始 ＋ 使用時開始時は説明、使用時に全文低（説明分のみ）
MCP サーバーセッション開始ツール名（スキーマは遅延）低
Code intelligence編集後・オンデマンド診断、定義・参照・型情報低（ファイル読み込みを削減）
Subagents起動時新規コンテキストメインから分離
Hooksトリガー時原則なし（外部実行）ゼロ（出力を返す場合を除く）
  • 自分だけが叩くスキルは disable-model-invocation: true にすると説明文すら読み込まれずコストがゼロになります
  • 他人が書いたスキルは設定の skillOverrides でファイルを編集せずに可視性を制御できます
  • /context で内訳、/mcp でサーバーごとのトークンコストを確認できます

9-7. この章の持ち帰り

5 つの拡張機能は、決め手の 1 問と導入の症状さえ持っていれば迷いません。

覚えること仕事での効き目具体的な操作
拡張は「コンテキストに足す」か「ハーネスで割り込む」かの 2 種類新しい拡張が出ても、どちらかに分類すればコスト（コンテキストなら毎ターン課金）と確実さ（ハーネスなら決定論的）が先に予測できる図 1-1 の「拡張とオーケストレーション」、3-9 ガードレール
Skill か Subagent か＝コンテキストを分けるか設計の議論が 1 問で終わる。分けない＝Skill、分ける＝Subagent大量読み込み・並列なら Subagent
Hook か Skill か＝保証が要るか「.env を触らせない」は指示ではなく強制で書く。事故の芽を仕組みで潰せるガードレールは PreToolUse フック
症状が出てから足す最初から全部設定する必要はない。2 回間違えたら CLAUDE.md、3 回貼ったら Skill、毎回コピーしているなら MCP9-3 のトリガー表
自分専用スキルはコストをゼロにできる説明文すら読み込まれなくなる。スキルを増やしても固定費が増えないdisable-model-invocation: true
内訳を数字で見る「なんとなく重い」を具体的な削減対象に変えられる/context と /mcp
意外と知られていない

名前が衝突したときの挙動は、機能ごとにまったく違います。CLAUDE.md は加算（すべての階層が同時に入る）、Skills と Subagents は上書き、MCP サーバーは1 つの定義が丸ごと採用（フィールドのマージはしない）、Hooks はマージ（登録された全部が発火）。チームで設定を配るときに効いてきます。
