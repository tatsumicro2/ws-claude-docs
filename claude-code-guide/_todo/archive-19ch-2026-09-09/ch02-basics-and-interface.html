02

基本操作とインターフェース

CLI フラグ、スラッシュコマンド、キーボード操作、権限モード。日々の生産性はこの層の習熟でほぼ決まります。動作環境・インストール・用途別の手段もこの章に置きます。

原理との対応

この章は原理そのものではなく、図 1-1 のインターフェース（サーフェス・インストール・起動フラグ・コマンド・キー操作）とガードレール（権限モード）の実装です。インターフェースは「コンテキストの最初の 1 行をどこから入れるか」、権限モードは「止められるのはツール実行の直前だけ」（3-9 ガードレール）を Shift+Tab 一つに畳んだものです。Esc で止める・実行中に文章を送る（2-3）は、エージェントループ（3-9 ループ）の周回に人が途中から割り込む操作面にあたります。廃れないのは「副作用はループでしか起きず、権限はその直前で効く」という構造で、フラグ名・コマンド名・キー割り当て・モードの既定値はバージョンごとに変わります。

2-1. CLI の起動パターンと主要フラグ

claude                        # 対話セッション
claude "テストを直して"         # 初期プロンプト付きで起動
claude -p "…"                 # 非対話（print）モード：CI / スクリプト向け
claude --continue             # 直前のセッションを再開
claude --resume               # セッションを選んで再開
claude --model opus           # モデル指定
claude --permission-mode plan # 権限モード指定で起動
claude --worktree             # 隔離した git worktree で起動
tail -200 app.log | claude -p "異常があれば教えて"   # パイプ入力
用途代表フラグ
実行制御--print/-p --output-format(text/json/stream-json) --max-turns --max-budget-usd
モデル・推論--model --effort --fallback-model --advisor
権限・ツール--permission-mode --allowedTools --disallowedTools --tools ／ --dangerously-skip-permissions（⚠ すべての確認を飛ばす。隔離環境以外では使わない。2-4 参照）
コンテキスト--add-dir --settings --setting-sources --append-system-prompt
拡張--agents（JSON で即席サブエージェント） --mcp-config --plugin-dir --plugin-url
セッション--session-id --fork-session --from-pr --name --teleport --cloud
診断--debug --verbose --safe-mode --version

2-2. コマンド一覧（ワークフロー別）

セッション内で / を打つと一覧が出ます。以下は用途別の代表例です（可用性はプラン・プラットフォームで異なります）。

場面コマンド
初期セットアップ/init（CLAUDE.md 生成）/memory /permissions /mcp /doctor /config /terminal-setup
タスク中/plan /model /effort /context /compact /btw（脇道質問）/goal
並列実行/tasks /background（/bg）/batch /workflows
レビュー・リリース/diff /code-review /review(PR) /security-review /simplify
セッション管理/clear /resume /branch /fork /rename /export /rewind /recap
拡張管理/skills /agents /plugin /hooks /reload-plugins /reload-skills
環境移動/desktop /ide /teleport /remote-control /mobile /chrome /cd /add-dir
運用・状況確認/status /usage /cost /stats /insights /statusline
困ったとき/doctor /debug /feedback /help /release-notes
構造の理解

コマンドには 3 種類あります。組み込みコマンド（CLI に実装された固定動作）、バンドルされたスキル（/code-review、/batch、/debug、/run、/verify など。中身はプロンプト）、バンドルされたワークフロー（多数のサブエージェントに展開）。自作のスキルも同じ /名前 で呼べます。

試してみる：コマンドを探す 
/help          # コマンド一覧を表示

プロンプトで / を打つと、その場で絞り込み補完が出ます。

2-3. 対話モードのキー操作

キー動作
Esc実行中のアクションを即停止（コンテキストは保持）
Esc ×2巻き戻しメニュー（/rewind と同じ）。入力欄が空のときだけ。文字が残っているときは入力のクリアになる
Shift+Tab権限モードの切り替え
Ctrl+Oトランスクリプトビューアの開閉。ツール呼び出しや思考を含む全履歴を遡れる（閉じるのは Esc／Ctrl+C／もう一度 Ctrl+O）
Ctrl+Tタスクリスト（チェックリスト）の表示切替（6-2）
Ctrl+B実行中のタスクをバックグラウンドに送る
Ctrl+G入力中の内容を既定のテキストエディタで開く（Ctrl+X Ctrl+E も可）
Ctrl+Rコマンド履歴の逆順検索
Ctrl+Eトランスクリプトビューア内で「すべて表示」を切替。通常入力では行末へ移動
Option/Alt+T拡張思考のオン・オフ
Shift+Enter改行（未対応ターミナルは /terminal-setup）
! プレフィックスシェルモード。v2.1.186 以降は出力が届くと Claude が自動で応答する（通常のプロンプトと同じ課金が発生。旧挙動に戻すには設定 respondToBashCommands: false）
@ / #ファイル参照 / メモリへの追記

Vim モード（/config → エディタモード、または settings.json の "editorMode": "vim"。/vim コマンドは v2.1.92 で削除）、音声入力（/voice）、フルスクリーンレンダリング（/tui fullscreen）、スクリーンリーダー対応、キーバインドのカスタマイズ（~/.claude/keybindings.json）も利用できます。

試してみる：キー操作を体験する 
!git status    # 「!」でシェルモード。出力が次のメッセージに添えられる

Shift+Tab（権限モード切替）、Esc 2回（巻き戻し）、Ctrl+O（トランスクリプトを開いて Esc で閉じる）も試してください。

2-4. 権限モード

Shift+Tab が巡回するのは default（Manual）→ acceptEdits → plan の 3 つです。auto はアカウントが利用条件を満たすときだけ、bypassPermissions は有効化フラグ付きで起動したときだけサイクルに加わり、dontAsk はサイクルに現れず --permission-mode dontAsk でのみ設定します。モードは「ベースライン」で、この上に個別の許可／確認／拒否ルールを重ねます。

モード確認なしで実行されるもの最適な用途
default（UI 表記：Manual）読み取りのみ導入初期、機密性の高い作業
acceptEdits読み取り＋ファイル編集＋一般的な FS コマンド（mkdir/mv/cp 等）レビューしながらの反復開発
plan読み取りのみ（編集せず計画を提案）変更前の調査・設計
autoすべて。ただしバックグラウンドの安全チェック（分類器）付き長時間の自律タスク。Pro / Max / Team ではターミナル・VS Code の既定の開始モード（v2.1.228 以降）。claude -p・Enterprise・API キー・Bedrock 等は default のまま。設定で変えるならユーザー設定の defaultMode（プロジェクト設定の auto は無視される）
dontAsk事前承認済みツールのみロックダウンした CI / スクリプト
bypassPermissionsすべて（チェックなし）⚠ 隔離コンテナ・VM のみ
  • bypassPermissions 以外では、保護されたパス（リポジトリ状態や Claude 自身の設定）への書き込みは自動承認されません。
  • 拒否ルール・確認ルールは bypassPermissions を含むすべてのモードで有効です。
  • 既定モードは設定の permissions.defaultMode で固定できます。
試してみる：Plan Mode で起動 
claude --permission-mode plan

起動したら、そのまま次のように依頼します（このモードではソースは編集されません）。

README.md と主要な設定ファイルを読んで、テストを追加する計画を立てて
最初に決めておくこと

bypassPermissions と --dangerously-skip-permissions は、Claude が確認なしにあらゆるコマンドを実行できる状態です（rm も git push も通ります）。ローカルの実プロジェクトでは使わず、使うなら dev container・VM・クラウドセッションなどの隔離環境に限定してください。日常は acceptEdits、確認を減らしたいときは安全チェック付きの auto が現実的な選択です。

2-6. インストールと最初の起動

ネイティブインストール（推奨）

# macOS / Linux / WSL
curl -fsSL https://claude.ai/install.sh | bash

# Windows PowerShell
irm https://claude.ai/install.ps1 | iex

パッケージマネージャ経由

brew install --cask claude-code        # Homebrew（安定版チャネル）
winget install Anthropic.ClaudeCode    # WinGet

起動

cd your-project

2-8. この章の持ち帰り

日々の生産性はこの層でほぼ決まります。覚えるキーは 3 つ、フラグは 2 つで足ります。

覚えること仕事での効き目具体的な操作
インターフェースとガードレールは、ループの前後に付いた実装新しいサーフェスやモードが出ても、「コンテキストをどこから入れるか」か「ツール実行の直前で何を通すか」のどちらかとして位置づけられる図 1-1 のインターフェースとガードレール、3-9 ガードレール
Shift+Tab で権限モードを回す確認ダイアログの頻度を作業内容に合わせて即座に変えられる。日常は acceptEdits が現実的default → acceptEdits → plan
Esc は「止める」、Esc 2 回は「戻す」暴走を 1 打鍵で止められる安心感が、任せられる範囲を広げる。コンテキストは保持されるEsc / Esc ×2（＝/rewind）
Ctrl+O でトランスクリプトを読む「なぜその結論になったか」を追える唯一の手段。レビューや障害報告で根拠を示せるCtrl+O（Esc で閉じる）
ログ調査はパイプで一撃ファイルに保存して読ませる手間が要らない。障害対応の初動が速くなるtail -200 app.log | claude -p "異常があれば教えて"
調査だけさせたいときは plan で起動「勝手に直された」が起きない。設計レビュー前の調査に向くclaude --permission-mode plan
意外と知られていない

Esc 2 回が巻き戻しになるのは、入力欄が空のときだけです。文字が残っていると入力のクリアになります。もう一つ、! のシェルモードは v2.1.186 以降出力が届くと Claude が自動で応答します——通常のプロンプトと同じ課金が発生するので、単に手元でコマンドを打ちたいだけなら設定 respondToBashCommands: false で旧挙動に戻せます。
