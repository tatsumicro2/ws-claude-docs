13

MCP（Model Context Protocol）

MCP は AI ツールを外部データソースに接続するためのオープン標準です。 これにより Claude Code は、DB のクエリ、Jira の更新、Slack からのデータ取得、ブラウザ操作などを行えます。

原理との対応

この章は図 1-1 の「MCP（外部接続）」で、原理でいえばツール使用（Function Calling）の実装です（3-9 ツール使用）。組み込みツールではハーネスが定義と実行の両方を持っていましたが、MCP は定義と実行を外部サーバーに委ね、ハーネスは仲介役になる標準です。往復の形は変わりません——定義がコンテキストに入り、モデルは「このツールをこの引数で」と選ぶだけで、実行はハーネスがサーバーへ取り次ぎ、結果はコンテキストに戻ります。「MCP を足すと重くなる」の正体はここにあり、サーバーが持つツール定義がそのままコンテキストを消費するため、毎ターン丸ごと送る 3-9 コンテキスト の固定費が増えます（13-4 の遅延ロードはその対策）。廃れないのはこの往復の構造で、変わるのはトランスポートの種類、ツール検索の既定値、claude mcp add の構文です。

13-1. MCP の位置づけ

MCP は能力（外部システムへの接続）を与え、Skill はそれを使う知識（スキーマ・典型クエリ・社内ルール）を与えます。両者はセットで使います（→ 9-2）。

接続前の注意

信頼の確認

外部コンテンツを取得するサーバーはプロンプトインジェクションのリスクにさらされます。自作するか、信頼できる提供元のサーバーのみを使ってください。Anthropic はディレクトリ掲載時に基準審査を行いますが、MCP サーバーのセキュリティ監査・管理は行いません。

13-2. サーバーの追加方法

# リモート HTTP サーバー
claude mcp add --transport http notion https://mcp.notion.com/mcp

# 認証ヘッダー付き
claude mcp add --transport http api https://api.example.com/mcp \
  --header "Authorization: Bearer ${API_KEY}"

# ローカル stdio サーバー（-- の後はそのままサーバーへ渡される）
claude mcp add airtable --env AIRTABLE_API_KEY=xxx \
  -- npx -y airtable-mcp-server

# 状態確認 / 認証 / 再接続
claude mcp list
claude mcp login <server>
/mcp                      # セッション内で状態とトークンコストを確認

トランスポートは HTTP（推奨）、stdio（ローカルプロセス）、WebSocket、SSE（非推奨）。リモートサーバーは OAuth 認証に対応します。

試してみる：接続状況を確認する

ターミナルで：

claude mcp list
Checking MCP server health…

code-rag: /path/to/code-rag-mcp  - ✔ Connected

サーバーごとに ✔ Connected / 失敗理由が並びます。セッション内では /mcp（ターミナルに貼ると command not found になります）で、サーバーごとのトークンコストまで確認できます。

13-3. インストールスコープ

スコープ読み込み対象チーム共有保存場所
ローカル（既定）現在のプロジェクトのみ×~/.claude.json（プロジェクトパス配下）
プロジェクト現在のプロジェクトのみ○（バージョン管理）リポジトリルートの .mcp.json
ユーザー全プロジェクト×~/.claude.json

同名サーバーが複数あるときの優先順位は 5-6 のとおり（ローカルが最優先）。1 つの定義が丸ごと採用され、フィールドのマージは行われません。

.mcp.json のプロジェクトスコープサーバーは、初回利用時に承認が必要です（claude mcp reset-project-choices でリセット）。

13-4. コンテキスト効率とガバナンス

軸仕組み・設定確認・操作
コンテキスト効率MCP ツール検索が既定で有効。起動時はツール名だけを読み、完全な JSON スキーマは ToolSearch 経由で遅延ロード/mcp でサーバーごとのトークンコストを見て、使っていないサーバーは切断する
MCP ツールの出力サイズには上限がある特定ツールだけ引き上げられる
ガバナンス権限ルールで mcp__<server> / mcp__<server>__<tool> の許可・拒否を指定/permissions
組織は管理設定で、追加・接続できるサーバーを許可／拒否リストで制御できる管理コンソール
その他Claude Code 自体を MCP サーバーとして他ツールに公開することも可能—

13-5. この章の持ち帰り

MCP は強力ですが、先に CLI で足りないかを疑うのが公式の推奨です。

覚えること仕事での効き目具体的な操作
MCP は 3-9 のツール使用そのもの。定義はコンテキスト、実行はハーネスサーバーを 1 つ足すと何が起きるかを予測できる——増えるのは能力と、毎ターン送る定義分のコンテキスト。重さは定義の量で決まるので、/mcp の数字を見て残す・切るを設計できる3-9 ツール使用（往復の図）・3-9 コンテキスト（固定費）
CLI で届くなら MCP を使わないgh aws gcloud が使えるなら、接続もトークンも要らず安い公式のベストプラクティスにも明記
使っていないサーバーは切るツール定義が固定費として毎リクエストに乗る。数字で確認して落とす/mcp でサーバーごとのトークンコスト
MCP は能力、Skill は使う知識接続しただけでは使いこなせない。スキーマ・典型クエリ・社内ルールはスキルに書くセットで用意する
チーム共有は .mcp.jsonリポジトリにコミットでき、全員が同じ接続先を持てる初回利用時に各自の承認が要る
外部を取り込むサーバーはリスク源取得したコンテンツに仕込まれた指示で操られうる。提供元を選ぶ信頼できる提供元か自作のみ
意外と知られていない

/mcp はセッション内コマンドです。ターミナルに貼ると command not found になります——ターミナル側は claude mcp list。もう一つ、MCP ツール検索が既定で有効なので、起動時に読まれるのはツール名だけで、完全な JSON スキーマは必要になってから遅延ロードされます。「MCP を足すと重い」の程度は、昔の記事の印象より軽くなっています。
