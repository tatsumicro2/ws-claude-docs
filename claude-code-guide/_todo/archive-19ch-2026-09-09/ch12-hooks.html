12

Hooks（フック）

フックは Claude Code のライフサイクル上の特定イベントで必ず実行される仕組みです。 「お願い」ではなく「強制」。フォーマット、監査、ブロック、通知はここに置きます。

原理との対応

フックは、図 1-1 の「ガードレール」の実装で、原理でいえば「ハーネスで強制する」側です（3-9 ガードレール）。モデルを通さず、ハーネスがエージェントループの決まった位置（ツール実行の直前・直後、ターンの終わり）で必ず動かすので、決定論的に効きます。CLAUDE.md やスキルはコンテキストに指示を置く「文脈で頼む」であり、モデルが読んで従うことが多いだけで保証はありません——核となる 4 つのうち副作用を握るのはハーネスだけなので、強制できるのもハーネスだけで、フックは利用者がそこに自分の処理を差し込める入口です。exit 2 の stderr が Claude へのフィードバックになるのは、ツールの結果がコンテキストに戻る（3-9 ツール使用）からで、PostToolUse で Lint やテストを回すのは、「機械的な合否を毎周回のコンテキストに入れる」（3-9 ループ）を人手なしで成立させる操作です（ただし prompt・agent 型のフックは、発火は決定論的でも判定をモデルに委ねるので確率的です）。廃れないのは「守らせたい規則はコンテキストではなくハーネスに置く」という分業で、変わるのはイベント名の一覧、フックの種類、JSON の形です。

12-3. 設定方法と入出力

設定ファイル（~/.claude/settings.json、.claude/settings.json など）の hooks キーに定義します。/hooks メニューからも編集できます。

{
  "hooks": {
    "PostToolUse": [
      {
        "matcher": "Write|Edit",
        "hooks": [
          { "type": "command", "command": "jq -r '.tool_input.file_path' | xargs npx prettier --write" }
        ]
      }
    ]
  }
}

入出力の約束ごと

  • 入力：イベントの JSON コンテキストが stdin（コマンドフック）または POST ボディ（HTTP フック）で渡される。編集対象のパスを受け取る環境変数は用意されていないので、jq -r '.tool_input.file_path' のように stdin の JSON から取り出す（環境変数で渡るのは CLAUDE_PROJECT_DIR などに限られる）
  • 出力その 1（終了コード）：exit 0 = 通過、exit 2 = ブロックし、stderr の内容が Claude へのフィードバックになる
  • 出力その 2（構造化 JSON）：exit 0 ＋ JSON で決定を細かく制御。exit 2 と JSON の併用は不可（exit 2 のとき JSON は無視される）
  • フックの種類は 5 つ：command（シェル）／http（POST）／mcp_tool（既存の MCP ツールを呼ぶ）／prompt（LLM に判定させる）／agent（サブエージェントで検証）
#!/bin/bash
# PreToolUse: 危険な SQL をブロックする例
INPUT=$(cat)                                            # stdin の JSON を受け取る
COMMAND=$(echo "$INPUT" | jq -r '.tool_input.command')  # 実行されようとしているコマンド
if echo "$COMMAND" | grep -q "DROP TABLE"; then
  echo "Blocked: dropping tables is not allowed" >&2    # stderr が Claude へのフィードバック
  exit 2                                                # exit 2 = ブロック
fi
exit 0
試してみる：最小のフックを入れる 
/hooks        # メニューから対話的に追加するのが最も安全

ファイルで書くなら以下。.claude/settings.local.json が既にある場合は上書きされるので、既存があるときは手で追記してください。

mkdir -p .claudecat > .claude/settings.local.json <<'EOF'
{
  "hooks": {
    "Stop": [
      { "matcher": "", "hooks": [
        { "type": "command", "command": "echo \"turn finished at $(date)\" >> \"$CLAUDE_PROJECT_DIR/.claude/hook.log\"" }
      ]}
    ]
  }
}
EOF

セッションを開き直し、/hooks で登録を確認。1ターン話すと .claude/hook.log が増えます。
後始末：.claude/settings.local.json の hooks ブロックを削除。

12-4. 典型的なユースケース

PostToolUse
編集後の自動整形

Write/Edit にマッチさせて Prettier・gofmt・ruff を実行。Lint 結果はテキストとして Claude に返る。

PreToolUse
保護ファイルの編集を遮断

.env、本番設定、マイグレーション済みファイルへの書き込みを exit 2 で拒否。

Notification
入力待ちを通知

Claude が確認を求めたときに OS 通知・Slack・LINE などへ ping。

PostCompact
圧縮後の再注入

コンパクションで失われがちな重要コンテキストを再投入する。

ConfigChange
設定変更の監査

セッション中の設定変更を記録、あるいはブロックする。

Stop
ターン終了時の検証

作業ツリー全体をスキャンして未整形・未テストを検出。CI 的な最終チェック。

Bash 経由の変更に注意

Claude は Bash ツールからもファイルを変更できます。すべての変更を捕捉したい監査用途では、ターンごとに 1 回作業ツリーを走査する Stop フックを併用してください。

12-5. スコープとトラブルシューティング

  • フックはマージされる。ユーザー設定・プロジェクト設定・プラグイン・スキル／エージェント定義の全てが該当イベントで発火する
  • プロジェクト設定のフックは、そのフォルダのワークスペーストラストを承認した後に有効になる
  • スクリプトは ${CLAUDE_PROJECT_DIR} を使って絶対パスで参照すると安定する
  • 発火しないときは /hooks で登録状況を確認し、スクリプトを手動実行して終了コードを検証する
echo '{"tool_name":"Bash","tool_input":{"command":"ls"}}' | ./my-hook.sh
echo $?   # 終了コードを確認
セキュリティ

フックはあなたの権限で任意のシェルコマンドを実行します。他人が書いたフック（プラグイン・リポジトリ由来）は、信頼する前に必ず中身を読んでください。

12-6. この章の持ち帰り

フックは「お願い」を「強制」に変える唯一の層です。書き方の型さえ知れば 5 分で入ります。

覚えること仕事での効き目具体的な操作
ハーネスで強制する（決定論的）CLAUDE.md・スキルは「文脈で頼む」で確率的。守られなければ困る規則はフックへ、守られると嬉しい程度の指示はコンテキストへ、と置き場所が一意に決まる3-9 ガードレール、3-9 ループ
まず /hooks から入れる既存の settings.local.json を上書きして壊す事故を避けられる/hooks で対話的に追加
パスは stdin の JSON から取る編集対象のパスを渡す環境変数は用意されていない。ここで詰まる人が多いjq -r '.tool_input.file_path'
exit 2 でブロック、stderr がフィードバック禁止するだけでなく「なぜ駄目か」を Claude に伝えて別の手を打たせられるecho "理由" >&2; exit 2
Bash 経由の変更は PostToolUse で捕まらない監査目的なら取りこぼす。ターンごとに作業ツリーを走査する形にするStop フックで全体スキャン
整形・Lint・通知をここに移す毎回頼まなくても必ず走る。レビューでの指摘が定型作業から消えるPostToolUse に Write|Edit でマッチ
意外と知られていない

フックの種類は 5 つあり、シェルコマンドだけではありません。command のほかに http（POST）、mcp_tool（既存の MCP ツールを呼ぶ）、prompt（LLM に判定させる）、agent（サブエージェントで検証）があります。「機械的には判定できないが必ずチェックしたい」ものを prompt フックに置けるのは、意外と知られていない使い道です。なお exit 2 と構造化 JSON の併用はできません。
