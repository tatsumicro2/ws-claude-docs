Claude Code 体系的入門/第3章
03

コアメカニズム

Claude Code を「なんとなく賢いツール」から「挙動が予測できる道具」に変えるのが、この章です。 エージェントループ・モデル・ツール・コンテキストウィンドウ・セッションの 5 つが土台になります。

原理との対応

この章は 図 1-1 の核——LLM・コンテキストウィンドウ・ツール使用・エージェントループ——を Claude Code の部品名でたどる章です。各節の根拠になる原理は章末の 3-9 にまとめてあり、下表がその対応です。廃れないのはその原理のほうで、モデル名・ウィンドウ幅・ツールの数・タイムアウトの秒数といった本文の数値はバージョンで変わります。

3-1. エージェントループ（Agentic loop）

タスクを与えると、Claude は ①コンテキストの収集 → ②アクションの実行 → ③結果の検証 という 3 フェーズを、必要なだけ繰り返します。フェーズは厳密には分かれておらず、互いに溶け合います。

  • ループを駆動するのは 推論するモデル（3-3）と 行動するツール（3-4）の 2 要素です。
  • ユーザーもループの一部です。Esc で即停止、あるいは実行中に文章を送って軌道修正できます。
試してみる：ループを観察する 
claude "READMEを読んで、このプロジェクトのテスト実行方法を教えて"

Ctrl+O でトランスクリプトビューアを開くと、思考とツール使用を含む履歴を遡れます（Esc で閉じる）。

3-2. エージェントハーネス（Agentic harness）

モデル単体は文章を返すだけです。ループを回せるのは、モデルを取り巻く仕掛け——エージェントハーネス——があるからです。Claude Code の正体はこれです。

ハーネスの要素あなたが調整できるもの本資料
ツール群権限ルールでの許可・拒否、MCP サーバーの追加、スキル3-4 / 10 章 / 13 章
コンテキスト管理CLAUDE.md、自動メモリ、コンパクション、サブエージェントへの委譲3-6 / 4 章
実行環境作業ディレクトリ、サンドボックス、worktree15-4
権限と安全装置権限モード、フック、チェックポイント2-4 / 12 章 / 3-7
「4 要素」は公式の分類ではありません

公式が定義しているのは「モデルにツール・コンテキスト・実行環境を与えてループを回すソフトウェア層」というハーネスの役割までで、構成要素の数え方は決まっていません（エージェントループ自体をハーネスに含める整理もあります）。上の 4 つは、利用者が調整できる場所として本資料が整理したものです。

システムプロンプト — ハーネスが毎回先頭に置くもの

上の 4 つはあなたが調整できるものですが、ハーネスはもう 1 つ、調整できないのに毎回必ず送られるものをモデルに与えています。システムプロンプトです。実際に API へ送られるリクエストは、次の 3 つの領域に分かれています。

領域中身誰が書くか
systemシステムプロンプト。Claude Code という製品そのものの指示Anthropic（CLI に同梱）
toolsそのセッションで使えるツールの定義一式（3-4）Claude Code が組み立てる
messagesあなたのプロンプトと、それ以降の会話・ツール結果あなたと Claude

システムプロンプトに書かれているのは、おおむね次の 4 種類です。

  • 役割の定義 — 対話型エージェントとしてどう振る舞うか
  • ツールの使い分けの方針 — いつ Read で読み、いつ Bash に回すか
  • 安全上の規則 — 破壊的な操作の確認、取り込んだ外部コンテンツの扱い（15-5）
  • 環境情報 — 作業ディレクトリ、日付、OS、モデル名、git の状態

あなたが書くものではなく、Claude Code のバージョンが上がれば中身も変わります。手を出せるのは 3 通りだけです。

したいこと手段本資料
末尾に付け足す--append-system-prompt4-6
振る舞いごと差し替える出力スタイル（output style）8-2
サブエージェントに別のものを与えるエージェント定義の本文が、そのままそのエージェントのシステムプロンプトになる11-2
CLAUDE.md との違い

CLAUDE.md はあなたが書く指示、システムプロンプトは製品が持つ指示で、置かれる領域そのものが別です。/context が「System prompt」と「Memory files」を別の行で表示するのはこのためです。7-3 のプロンプトキャッシュで第 1 層がシステムプロンプトなのは、これが毎リクエストの先頭に来る、最も動かない部分だから。tools がその直後に続くので、セッション途中でツールを足すと、そこから後ろが全て再計算になります。

試してみる：3 つの領域の大きさを見る 
/context

System prompt と System tools の 2 行が、ここで説明した system と tools。Messages が会話です。この 3 つが、ループの周回ごとに丸ごと送り直されています。

同じハーネスを自分のプログラムから使える

このハーネスをライブラリとして切り出したものが Claude Agent SDK です。Claude Code そのものではなく、同じ仕組みの上に独自のエージェントを組み立てられます（16-4）。

3-4. 組み込みツール

組み込みツール（built-in tools）は Claude Code が既定で備えている手足です。MCP で足すカスタムツールとは別物で、スキルは既存の Skill ツール経由で動くためツールを増やしません。

数はバージョンと環境で変わる

公式のツールリファレンスに載っているのは 40 種類あまりですが、実際にセッションへ渡されるツールはバージョン・プラン・プラットフォームで増減します（本表は v2.1.251 時点。公式表に未掲載でも提供されるものがあります——実測）。手元の断面は下の「試してみる」で確認できます。

試してみる：どのツールが使われたか見る

対話セッションでは Ctrl+O のトランスクリプトビューアで確認できます。非対話モードでは --output-format stream-json --verbose を使います（--verbose だけでは最終回答しか出ません）。

claude -p "README を読んでテスト実行方法を1行で答えて" --output-format stream-json --verbose

1 行 1 イベントの生 JSON が流れます。jq で「使われたツールと引数」だけに絞ると読めます。

claude -p "README を読んでテスト実行方法を1行で答えて" --output-format stream-json --verbose \
  | jq -rc 'select(.type=="assistant") | .message.content[] | select(.type=="tool_use") | [.name,(.input|tostring)] | @tsv'
Read    {"file_path":"/path/to/README.md"}

README を Read で読むか Bash の cat で読むかは、そのときの判断で変わります。「なぜその結論になったか」を追うときの基本手段です。最初の 1 行（system イベント）の tools 配列が、そのセッションに渡されたツールの一覧です。

3-6. コンテキストウィンドウ

コンテキストウィンドウ（context window）には、会話履歴・ファイル内容・コマンド出力・CLAUDE.md・自動メモリ・読み込まれたスキル・システム指示が同居します。ここが Claude Code 運用の最大の制約です。

モデル別のウィンドウ

3-8. ツール別の落とし穴

ツール名を知っていても、挙動を知らないと「なぜそうなるのか」が分かりません。見落とされやすいものを挙げます。

ツール見落としやすい挙動実務での意味
Bash コマンドごとに別プロセス。export した環境変数は引き継がれない venv や conda は起動前に有効化する。CLAUDE_ENV_FILE でも渡せる
cd の作業ディレクトリは引き継がれる（作業ディレクトリの内側にいる限り） 外に出ると自動リセットされ Shell cwd was reset to ... が付く
タイムアウトは既定 2 分・上限 10 分。超えたコマンドは停止ではなくバックグラウンドへ移る /tasks で確認・停止する。sleep 始まりと git を含むものは移らず停止
結果に載る出力は約 30,000 文字まで。超えるとファイルに保存されパスだけ返る BASH_MAX_OUTPUT_LENGTH で最大 150,000 まで拡張可
Read 大きいファイルは切られ、PARTIAL view の注記付きで先頭だけ返る 「読んだはずなのに後半を知らない」の原因
画像は視覚的な内容として渡る。PDF は 10 ページ超なら pages で範囲指定（1 回 20 ページまで） スクリーンショットを貼れば見て判断できる
ディレクトリは読めない 一覧は ls などシェル側で取る
Grep .gitignore を尊重する。ripgrep ベースで POSIX grep とは正規表現が違う 無視対象を探すならパスを直接渡す。interface{} 等はエスケープが要る
Glob .gitignore を尊重しない（Grep と逆）。結果は更新時刻順で最大 100 件 ビルド生成物まで拾う。件数が多いならパターンを絞る
WebFetch 取得後に小さいモデルが指定プロンプトで抽出する。設計上ロスがある 「書かれていない」は聞き方が悪かっただけかもしれない。聞き直す
別ホストへのリダイレクトは追わず返す。レスポンスは 15 分キャッシュ。認証 URL は不可 リダイレクト先は改めて呼び直す
WebSearch 1 回の呼び出しで最大 8 件のバックエンド検索を発行。返るのはタイトルと URL だけで、ページ本文は取らない 本文が要るなら WebFetch で追う。権限ルールは裸の WebSearch のみで指定子を書けない
AskUserQuestion 質問は既定で答えるまで開いたまま askUserQuestionTimeout を 60s / 5m / 10m にすると自動で閉じて続行。権限プロンプトとプラン承認は自動解決しない

3-9. 原理 — 製品が変わっても残る事実

この章の部品は、どれも 図 1-1 の核——LLM・コンテキストウィンドウ・ツール使用・エージェントループ——の実装です。部品の名前・上限値・既定値は版で変わりますが、次の事実は Claude Code 以外のエージェントでも変わりません。他の章の「原理との対応」は、ここを指しています。

LLM — 記憶も副作用も持たない

モデルは、コンテキストを受け取り、次のトークンを確率的に選んで返す状態を持たない推論エンジンです。

事実帰結Claude Code での現れ方
記憶を持たない「覚えている」ように見えるのは、毎回これまでの全部を渡し直しているから。コンテキストに無いものは知らない「さっき言ったよね」が通じない。指示はコンテキストに置く（3-6、4 章）
副作用を持たないファイルを書くのもコマンドを打つのもモデルではない。「したい」と構造化して言うだけ実行はハーネス側（3-2）。止める場所もそこに集まる
確率的である同じ入力でも出力は揺れる。再現性が要る処理はモデルの外（テスト・フック）に置く同じ依頼で違う結果が返る。揺れて困る処理は検証で受ける（5-5、12 章）
推論も出力である「考える」時間はトークンとして生成され、出力として課金される。量は調整できるが無料ではないモデル選択と努力レベル（3-3）

コンテキストウィンドウ — 有限で、毎ターン丸ごと送る

セッションの状態はコンテキストウィンドウの中身だけです。システムプロンプト・CLAUDE.md・自動メモリ・読み込まれたスキル・会話履歴・読んだファイル・コマンド出力が、毎ターンまとめてモデルに送られます。

事実帰結Claude Code での現れ方
有限である上限に近づくと古いツール出力から消され、次に会話が要約される。要約の後、元の文言は無い/context・自動コンパクション・/compact（3-6）
毎ターン丸ごと送るコストと時間はコンテキストの長さに比例する。会話が長いほど 1 往復が高く遅いコストの構造（7-2）。CLAUDE.md は毎ターン送られる固定費（4 章）
先頭一致でキャッシュされる先頭（システムプロンプト・CLAUDE.md）を変えなければ再利用される。途中でモデルや設定を変えると作り直しプロンプトキャッシュ（7-3）
中身は目で見える会話は 1 行 1 イベントの JSONL としてディスクに保存される。「覚えている」の正体はこれを読み直していること--resume・セッション（3-7）

金額は変わりますが構造は変わりません。出力トークン（推論を含む）は入力より高く、キャッシュに乗った入力は乗らない入力より安い。「短く保つ」「先頭を固定する」「出力を無駄に増やさない」の 3 つが、金額と速度の両方に効きます。

ツール使用（Function Calling）— モデルは選ぶだけで、実行しない

ハーネスがツールの定義（名前・説明・引数のスキーマ）をコンテキストと一緒に渡し、モデルは「このツールを、この引数で」を構造化して返す（tool_use）。ハーネスが権限を確認して実行し、結果（tool_result）をコンテキストの末尾に足して再び渡す。LLM に行動させるどの道具も、この往復で動いています。

事実帰結Claude Code での現れ方
ツールの定義はコンテキストに入るツールを増やすほど毎ターンのトークンが増える。定義の遅延ロードはこの対策組み込みツール（3-4）・MCP のツール検索（13-4）
モデルは選ぶだけで、実行しない実行の直前に、人・ルール・フックが割り込める。ガードレールはここで効く権限モード（2-4）・フック（12 章）
結果もコンテキストに戻る巨大なコマンド出力はそのままコンテキストを圧迫する。返す前に絞る価値があるツール別の落とし穴（3-8）
スキーマと説明文が精度を決める曖昧な定義は呼び出しがぶれる。MCP サーバーの良し悪しも結局はここMCP（13 章）
意外と知られていない

ツールを 1 つでも渡すと、API 側でツール使用のためのシステムプロンプトが自動で追加されます（数百トークン規模。モデルごとの値は公式の表にあります）。ツール定義そのものも入力トークンとして課金されます。「MCP を足すと重くなる」の正体は、この 2 つの足し算です。

エージェントループ — 合否が返る領域でだけ収束する

モデルの出力を実行し、結果をコンテキストに足して、またモデルへ渡す。この反復（3-1）が収束する条件は、周回ごとに機械的な合否がコンテキストに入ることです。テスト・型検査・Lint・ビルドの合否は、次の周回の入力になります。合否が返らない仕事では、ループは「それらしいもの」を出して止まるしかありません。

  1. 対象をテキストで表現できる — コンテキストに入らないものは、モデルからは見えない
  2. 結果を機械が判定できる — ループは合否が返ってくる領域でだけ収束する
  3. 操作を巻き戻せる — 外れた周回のコストが低い（git、チェックポイント）

ソフトウェア開発はこの 3 条件が揃っている領域で、名前に「Code」が付く理由もここにあります。3 条件が揃う仕事（設定ファイル、インフラ定義、データ変換、原稿の校正）ならコードでなくても同じように使え、揃わない仕事——正解が主観的、実行して確かめられない、失敗が取り返しつかない——では、回すほど良くなる前提が崩れます。「テストを先に書いて」（5-1）やプランモード、フックでの自動検証（12-4）は、すべてこの条件を満たすための操作です。

メモリ — 外に残す・分ける・縮める・捨てる

コンテキストはセッションが終われば消え、長くなれば要約されます。それでも残したいもの、分けたいものに対して、原理から出てくる操作は 4 つしかありません。

操作原理Claude Code での現れ方
外に残す（永続化）コンテキストの外——ファイル——に書いて、次のセッションの先頭に読み込む。人が書くものとモデルが書くものの 2 系統CLAUDE.md・rules（人）／自動メモリ（モデル）— 4 章
分ける（分離）別のコンテキストで別のモデル呼び出しを回し、要約だけを元に戻す。過程は要らず結果だけ要る仕事に効くSubagents（11-1）
縮める（圧縮）コンテキストを要約に置き換える。損失がある。何を残すかは指示できる/compact・自動コンパクション（3-6）
捨てる（新規開始）空のコンテキストから始める。戻ってくるのは永続化したものだけ/clear・新しいセッション

ここから 3 つの帰結が出ます。セッションは互いに独立で、橋渡しは永続化だけ。永続化したものは文脈であって強制ではない（CLAUDE.md も自動メモリもコンテキストの先頭に足されるだけで、モデルが読んで従う「ことが多い」）。分離すると過程は見えなくなる（要約だけが戻るので安く速いが、途中で何をしたかは残らない）。

ガードレール — 副作用はハーネスにしかない

モデルは何も実行できず、実行はすべてハーネスで起きます。だから止める・制限する・戻すはハーネス側に置きます。手段は性質の違う 2 種類に分かれ、守られなければならない規則はコンテキストではなくハーネスに置くのが公式ドキュメントも明示する方針です。

種類仕組み確実さClaude Code での現れ方
ハーネスで強制するモデルを通さず、実行の直前・直後にハーネスが必ず動かす決定論的。毎回同じように効く権限ルール・フック・サンドボックス — 12 章、15 章
文脈で頼むコンテキストに指示を置き、モデルが読んで従う確率的。従うことが多いが保証はないプロンプト・CLAUDE.md・スキル — 4 章、10 章

CLAUDE.md に「.env を触るな」と書くのは依頼、PreToolUse フックで書き込みをブロックするのは強制です。また巻き戻せるのはハーネスが自分で触ったものだけで、ファイル編集はスナップショットから戻せますが、DB・API・デプロイなど外部の副作用は戻せません。外界に触れるのはハーネスだけなので、権限・サンドボックス・確認ダイアログはすべてツール実行の直前に集まります（3-7、15-1）。

Bash の結果に載る出力は約 30,000 文字までです。超えるとファイルに保存されパスだけが返るため、長いログを丸ごと読ませたつもりが読まれていないことがあります。BASH_MAX_OUTPUT_LENGTH で最大 150,000 まで広げられますが、そもそも grep で絞ってから渡すほうが速くて安上がりです。
