Claude Code は、LLM にツールを持たせ、ループで回すプログラムです。この章では、その部品のうち廃れない部分だけを順に取り出します。ここを読めば、残りの章はすべてこの章のどれかの実装として読めます。

1-1. 一言でいうと

まず 1 枚で全体を見ます。AI エージェントは、一般にLLM・コンテキストウィンドウ・ツール使用・エージェントループの 4 つを核とし、その周りをメモリ・ガードレール・拡張・観測性が取り囲む構造をしています。Claude Code はその一実装で、図の各要素の下段が対応する機能です。この章の残りは、この図の核の部分を原理として説明します。

Claude Code は Anthropic の agentic コーディングツールです。公式ドキュメントの定義では、タスクを与えると「コンテキストを集め、行動し、結果を検証する」を必要なだけ繰り返すエージェントです。現在開いているファイルだけを見るインライン補完とは、動き方が根本から違います。

Read
コードベースを読む

ファイル検索・全文検索・依存関係の把握。プロジェクト全体が対象。

Write
ファイルを編集する

複数ファイルにまたがる協調的な編集。新規作成・リネーム・再編成まで行う。

Execute
コマンドを実行する

テスト、ビルド、git、パッケージマネージャ。コマンドラインでできることは基本的に実行できる。

Verify
結果を検証する

テスト実行やスクリーンショット比較で自分の作業を確認し、失敗すれば修正を繰り返す。

「認証のバグを直して」と依頼すると、関連ファイルの探索 → 複数ファイルの読み込み → 協調した編集 → テスト実行 → 必要ならコミット、という一連の流れを自律的に実行します。

1-2. 部品は 3 つ — 文字列・関数・ループ

数学が最終的に公理と推論規則に還元されるように、Claude Code も還元できます。機能の呼び名は数十ありますが、実体は次の 3 つだけです。第 2 章以降で扱う内容は、すべてこの 3 つのどれかを操作する話に帰着します。

要素実体性質
文字列コンテキスト（これまでのやりとり全部）セッション唯一の状態。ここに無いものは存在しない
関数モデル（Claude 本体）文字列を受け取り、文字列を返すだけ。記憶も副作用も持たない
ループハーネス（Claude Code というプログラム）関数の出力を実行し、結果を文字列の末尾に足して、また関数へ渡す

動作を 1 行で書くと、これがすべてです。

文字列 ← 文字列 ＋ ハーネスが実行した結果（モデル（文字列））     … 停止条件まで繰り返す

ファイルを編集するのも、テストを走らせるのも、モデルではありません。モデルは「編集したい」とテキストで書くだけで、実際に手を動かすのはハーネスです。この分業が、権限・セキュリティ・フックのすべての土台になっています。

一般的な呼び名との対応

この 3 つは本資料の言い方ですが、業界には対応する一般名があります。他のエージェントツールの説明や論文は、ほぼ次の 4 つの語で書かれています。4 つ目の「ツール使用」は要素ではなく、関数とループの接点です。

本資料の呼び名一般的な呼び名何を指すか他のツールでの現れ方
関数LLM／基盤モデル文字列を受け取り、次に来るトークンを確率的に選んで返す。記憶も副作用も持たない多くのツールが同じ数社のモデルを使う。ツール間の差は関数ではなく、残り 2 つに出る
文字列コンテキスト（ウィンドウ）／状態／メモリ関数に渡す入力の全部。会話・ファイル・ツール結果・指示「コンテキストエンジニアリング」「メモリ管理」「圧縮・要約」は、すべてこの文字列の操作
ループエージェントループ／ハーネス／オーケストレーター関数の出力を解釈して実行し、結果を文字列に足して関数へ戻すReAct（思考 → 行動 → 観察）は同じ構造を説明する概念モデル。2022 年の論文が起源†
関数とループの接点ツール使用（tool use）／関数呼び出し（function calling）ハーネスがツールの定義を文字列に含め、関数は「このツールをこの引数で」と構造化した文字列で返し、ハーネスが実行して結果を文字列に足すClaude API では tool_use ブロックと tool_result ブロックの往復（1-5）。MCP はこの定義と実行を外部サーバーに委ねる標準
† ReAct は Claude Code の実装根拠ではない

公式ドキュメントはループを「収集 → 実行 → 検証」で説明しており（1-6）、ReAct（Yao ほか、2022）を実装の根拠にはしていません。ReAct を知る意味は、他のツールや論文の説明が読めるようになることにあります。内部実装は非公開なので、両者の対応づけは類推です（0-3）。

1-3. 関数 — 記憶も副作用も持たない

モデルは、文字列を受け取り、次に来るトークンを 1 つずつ確率的に選んで、文字列を返す関数です。この 1 文から、製品やモデルの世代が変わっても変わらない事実が 4 つ出てきます。

廃れない事実何が起きるか
記憶を持たない「覚えている」ように見えるのは、毎回これまでの全部を渡し直しているから。渡さなければ知らない（1-4）
副作用を持たないファイルを書くのも、コマンドを打つのも、モデルではない。モデルは「書きたい」とテキストで言うだけ（1-5）
確率的である同じ入力でも出力は揺れる。再現性が要る処理はモデルの外——テストやフック——に置く（1-6、1-8）
推論も出力である「考える」時間はトークンとして生成され、出力として課金される。考えさせる量は調整できるが、無料ではない

現れ方原理との対応詳細

努力レベル（/effort）推論に使う出力トークンの量を変える3-3
同じ依頼で違う結果が返る確率的。指示が悪いとは限らない。揺れて困る処理は検証で受ける5-5

1-4. 文字列 — 有限で、毎ターン丸ごと送る

関数に渡す文字列がコンテキストです。セッションの状態はこれだけで、ここに無いものは Claude にとって存在しません。

何が入っているか

公式ドキュメントの列挙では、次の 7 つです。

  • システム指示（ハーネスが付ける、あなたには見えない部分）
  • CLAUDE.md（あなたが書く指示）
  • 自動メモリ（モデルが自分で書き溜めたもの）
  • 読み込まれたスキル
  • 会話履歴
  • 読んだファイルの内容
  • コマンドの出力
廃れない事実帰結
有限である上限に近づくと、古いツール出力から消され、次に会話が要約される。要約の後、元の文言はもう無い
毎ターン丸ごと送るコストと時間は文字列の長さに比例して増える。会話が長いほど、1 往復が高く遅い
先頭一致でキャッシュされる先頭（システム指示・CLAUDE.md）を変えなければ再利用される。途中でモデルや設定を変えると作り直し
中身は目で見える会話は 1 行 1 イベントの JSONL としてディスクに保存されている。「覚えている」の正体はこれを読み直していること

コストの構造

金額は変わるので 7 章に置きますが、構造は変わりません。出力トークンは入力より高く、推論も出力として数えられ、キャッシュに乗った入力は乗らない入力より安い。したがって「文字列を短く保つ」「先頭を固定する」「出力（推論を含む）を無駄に増やさない」の 3 つが、金額と速度の両方に効きます。

プロンプトキャッシュ先頭一致の再利用。モデル・設定は冒頭で固定する7-3
CLAUDE.md・rules先頭に置かれる文字列。毎ターン送られる固定費4 章

1-6. ループ — 収集・実行・検証と、収束の条件

関数の出力を実行し、結果を文字列に足して、また関数へ渡す。これを繰り返すのがループで、Claude Code というプログラムの本体です。公式ドキュメントはこの周回を 収集（gather context）→ 実行（take action）→ 検証（verify results） の 3 フェーズで説明しています。

  • 3 つのフェーズはきれいに分かれず、混ざりながら進む。質問なら収集だけで終わり、バグ修正なら何周もする
  • 何周するかはモデルが決める。前の周回の結果を見て、次に何をするかを選ぶ
  • あなたもループの一部。Esc で止められ、実行中に文章を送って軌道修正できる

周回の図は 3-1 にあります。ここでは、ループがいつ「うまくいく」のかを扱います。

ループが収束する条件

周回ごとに、機械的な合否が文字列に入ること。これがすべてです。テスト・型検査・Lint・ビルドが返す合否は、次の周回の文字列になります。合否が返らない仕事では、ループは「それらしいもの」を出して止まるしかありません。同じことを条件に直すと、次の 3 つになります。

  • 対象をテキストで表現できる — 文字列に入らないものは、関数からは見えない
  • 結果を機械が判定できる — ループは合否が返ってくる領域でだけ収束する
  • 操作を巻き戻せる — 外れた周回のコストが低い（git、チェックポイント）

ソフトウェア開発は、この 3 条件がたまたま完璧に揃っている領域でした。名前に「Code」が付いているのは、コードがこの条件を満たすからです。裏を返せば、3 条件が揃う仕事ならコードでなくても同じように使えます（設定ファイル、インフラ定義、データ変換、原稿の校正）。揃わない仕事——正解が主観的、実行して確かめられない、失敗が取り返しつかない——では、ループを回すほど良くなるという前提が崩れます。「これは Claude Code に向く仕事か」は、この 3 条件をいくつ満たすかで判断できます。

1-7. 記憶と分離 — 文字列の外に残す、文字列を分ける

文字列はセッションが終われば消え、長くなれば要約されます。それでも残したいもの、分けたいものをどう扱うか。原理から出てくる操作は 4 つしかありません。

操作原理Claude Code での現れ方詳細

1-8. 制御 — 副作用はループにしかない

関数は何も実行できません。実行はすべてハーネスで起きます。だから止める・制限する・戻すは、すべてハーネス側に置きます。制御の手段は、性質の違う 2 種類に分かれます。

種類仕組み確実さClaude Code での現れ方詳細
ループで強制する関数を通さず、実行の直前・直後にハーネスが必ず動かす決定論的。毎回同じように効く権限ルール・フック・サンドボックス12 章、15 章
文脈で頼む文字列に指示を置き、関数が読んで従う確率的。従うことが多いが、保証はないプロンプト・CLAUDE.md・スキル4 章、10 章
依頼と強制を混同しない

CLAUDE.md に「.env を触るな」と書くのは依頼です。PreToolUse フックで .env への書き込みをブロックするのは強制です。守られなければならない規則は、文字列ではなくループに置く——これは公式ドキュメントも明示している方針です。

廃れない事実帰結
巻き戻せるのは、ハーネスが自分で触ったものだけファイル編集は、編集前のスナップショットから戻せる。DB・API・デプロイなど外部の副作用は戻せない。だから実行前に止めるしかない
