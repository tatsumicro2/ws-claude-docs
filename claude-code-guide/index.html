Systematic Guide · 2026-08 版

Claude Code
体系的入門

Claude Code を題材に、LLM 全般に通用する廃れない基礎技術を主軸として、AI エージェントが動く仕組みを学ぶための資料です。 コマンドの一覧ではなく「なぜそう動くのか」を、Anthropic 公式ドキュメント（code.claude.com/docs/ja）を一次情報源として整理しました。 基礎概念から拡張機能、企業運用、自動化までを全 19 章（0〜18 章）で扱います。原理の部分は、別のエージェントツールにもそのまま持ち越せます。

作成日 2026-08-23 一次情報源 Claude Code 公式ドキュメント（日本語版） 対象 初学者 〜 チーム導入担当 構成 全 19 章（0〜18）
  1. CHAPTER 00

    この資料について

    何を主軸にし、何を周辺に置き、何を載せないか。読む前に、この資料の立場と情報ソースの扱いを先に示します。

    2 sections
  2. CHAPTER 01

    Claude Code とは

    Claude Code は、LLM にツールを持たせ、ループで回すプログラムです。図を 1 枚示し、どの章がその図のどこを扱うかを地図として渡します。

    1 sections
  3. CHAPTER 02

    基本操作とインターフェース

    CLI フラグ、スラッシュコマンド、キーボード操作、権限モード。日々の生産性はこの層の習熟でほぼ決まります。動作環境・インストール・用途別の手段もこの章に置きます。

    8 sections
  4. CHAPTER 03

    コアメカニズム

    Claude Code を「なんとなく賢いツール」から「挙動が予測できる道具」に変えるのが、この章です。 agentic ループ・モデル・ツール・コンテキストウィンドウ・セッションの 5 つが土台になります。

    10 sections
  5. CHAPTER 04

    記憶と指示

    セッションをまたいで知識を保持する仕組みは 2 系統あります。あなたが書く CLAUDE.md と、 Claude が自分で書く自動メモリです。どちらも「強制設定」ではなく「コンテキスト」である点が肝心です。

    7 sections
  6. CHAPTER 05

    ベストプラクティス

    公式の ベストプラクティス（旧 Anthropic Engineering の記事が統合されたページ）を、 「環境づくり」「対話」「セッション管理」「スケール」「失敗パターン」の 5 つに整理します。

    6 sections
  7. CHAPTER 06

    進行状況の可視化

    エージェントに任せる時間が長くなるほど、「今どこにいるのか」が見えないことが最大のストレスになります。Claude Code は、着手前の計画・実行中のチェックリスト・並列作業の進捗・資源の消費を、それぞれ別の仕組みで可

    8 sections
  8. CHAPTER 07

    コストと運用監視

    トークンは有限で有料です。「速く動かす」ことと「安く動かす」ことは、多くの場合同じ施策——コンテキスト管理に帰着します。

    8 sections
  9. CHAPTER 08

    用語集

    公式用語集（Glossary）から、本資料に登場する主要用語を抜粋・整理しました。

    3 sections
  10. CHAPTER 09

    拡張レイヤーの全体像

    Skills、Subagents、Hooks、MCP、Plugins。名前が似ていて混同しやすいので、 「いつ読み込まれるか」「誰が実行するか」という軸で整理します。ここが本資料の中核です。

    7 sections
  11. CHAPTER 10

    Skills（スキル）

    スキルは最も柔軟な拡張手段です。実体は SKILL.md という Markdown ファイル 1 枚。 Claude が自動で読み込むことも、/名前 であなたが呼び出すこともできます。

    8 sections
  12. CHAPTER 11

    Subagents と並列実行

    コンテキストは有限資源です。サブエージェントは別のコンテキストウィンドウで働き、要約だけを返すことで、 メインの会話を汚さずに調査・検証・並列作業を可能にします。

    6 sections
  13. CHAPTER 12

    Hooks（フック）

    フックは Claude Code のライフサイクル上の特定イベントで必ず実行される仕組みです。 「お願い」ではなく「強制」。フォーマット、監査、ブロック、通知はここに置きます。

    6 sections
  14. CHAPTER 13

    MCP（Model Context Protocol）

    MCP は AI ツールを外部データソースに接続するためのオープン標準です。 これにより Claude Code は、DB のクエリ、Jira の更新、Slack からのデータ取得、ブラウザ操作などを行えます。

    5 sections
  15. CHAPTER 14

    Plugins とマーケットプレイス

    プラグインは「配布のための箱」です。スキル・サブエージェント・フック・MCP サーバーを 1 つのインストール単位にまとめます。

    4 sections
  16. CHAPTER 15

    設定・権限・セキュリティ

    個人利用なら既定のままでも動きますが、チーム・組織で使うならこの章が本番です。 設定の階層、権限ルール、サンドボックス、企業向けデプロイまでを押さえます。

    9 sections
  17. CHAPTER 16

    自動化・CI/CD・Agent SDK

    対話の外へ出すと Claude Code は「開発者の道具」から「パイプラインの部品」になります。

    5 sections
  18. CHAPTER 17

    学習ロードマップ

    「どの順番で身につけるか」。各ステップに到達目標（できるようになること）を置いています。

    5 sections
  19. CHAPTER 18

    情報ソース一覧

    本資料の根拠と、継続学習のための情報源。公式／準公式／コミュニティを明確に区別して掲載します。
