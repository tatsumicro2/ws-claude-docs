Claude Code 体系的入門/第1章
01

概要・セットアップ・基本操作

Claude Code は、LLM にツールを持たせ、ループで回すプログラムです。この章では全体像を 1 枚の図で示し、インストールから起動・コマンド・キー操作まで、最初の 1 日で必要なことをまとめます。図のどの部分をどの章が扱うかも、ここで地図として渡します。

原理との対応

この章は原理そのものではなく、図 1-1 のインターフェース（サーフェス・インストール・起動フラグ・コマンド・キー操作）の実装です。インターフェースは「コンテキストの最初の 1 行をどこから入れるか」で、Esc で止める・実行中に文章を送る（1-5）は、エージェントループ（3-6 ループ）の周回に人が途中から割り込む操作面にあたります。廃れないのは「副作用はループでしか起きず、権限はその直前で効く」という構造で、フラグ名・コマンド名・キー割り当て・モードの既定値はバージョンごとに変わります。

1-1. Claude Code とは — AI エージェントのコア技術

Claude Code は Anthropic の agentic コーディングツールです。タスクを与えると「コンテキストを集め、行動し、結果を検証する」を必要なだけ繰り返し、コードベースを読み、複数ファイルを編集し、テストやビルドを実行して、自分の作業を確かめます。現在開いているファイルだけを見るインライン補完とは、動き方が根本から違います。

その構造は AI エージェント一般と同じで、LLM・コンテキストウィンドウ・ツール使用・エージェントループの 4 つを核に、メモリ・ガードレール・拡張・観測性が取り囲んでいます。図の上段が一般的な用語、下段が Claude Code での対応です。

この資料の地図

この資料は 6 章構成で、図の核と、それを囲む要素のうち日々の使い方に直結する部分を扱います。図の右側の「拡張とオーケストレーション」（サブエージェント・MCP・プラグイン）と CI/CD・Agent SDK は、この資料の範囲外です。

1-2. この資料の立場と情報ソース

この資料は、Claude Code をコマンドの集まりとしてではなく、AI エージェントの一実装として説明します。主軸に置くのは、Claude Code に限らず LLM を使うどの道具にも通用する基礎技術です。コマンドや固有の用語は、その基礎技術が製品にどう現れているかを示す例として扱います。

区分何か扱い
コア技術（主軸）LLM の性質、コンテキスト、ツール使用、エージェントループ、記憶と分離、制御図 1-1 で全体を示し、3-6 で原理として説明する。製品が変わっても変わらない部分
周辺技術指示の与え方、セッション、権限とフック、コンテキスト管理コア技術の応用として扱う。「コンテキストとループのどこを触るのか」を先に、操作を後に
実装の詳細コマンド名、フラグ、バージョン依存の数値、画面の操作必要な分だけ載せる。数値には「v2.1.x 以降」など条件を添え、暗記は求めない

原理から入ると、限界を予測できる（「この依頼はコンテキストに入らない」と試す前に分かる）、指示を設計できる（何をコンテキストに置き、何をループの外で強制するかを決められる）、知識を持ち越せる（モデル・コンテキスト・ハーネスの分業はどのエージェントツールでも同じ）の 3 つが変わります。前提知識はターミナル操作と Git の基礎だけで、機械学習の知識は要りません。

1-4. CLI の起動パターンと主要フラグ

claude                        # 対話セッション

claude -p "…"                 # 非対話（print）モード：スクリプト・パイプ向け

claude --resume               # セッションを選んで再開

1-5. コマンドとキー操作

セッション内で / を打つと一覧が出ます。コマンドには 3 種類あります。組み込みコマンド（CLI に実装された固定動作）、バンドルされたスキル（/code-review、/batch、/debug など。中身はプロンプト）、バンドルされたワークフローです。自作のスキル（2-6）も同じ /名前 で呼べます。

場面コマンド
初期セットアップ/init（CLAUDE.md 生成）/memory /permissions /doctor /config /terminal-setup
タスク中/plan /model /effort /context /compact /btw（脇道質問）
レビュー/diff /code-review /review(PR) /security-review /simplify
セッション管理/clear /resume /branch /fork /rename /export /rewind /recap
拡張・設定の管理/skills /hooks /permissions /reload-skills
運用・状況確認/status /usage /cost /stats /insights /statusline
困ったとき/doctor /debug /feedback /help /release-notes

対話モードのキー操作

キー動作
Esc実行中のアクションを即停止（コンテキストは保持）
Esc ×2巻き戻しメニュー（/rewind と同じ）。入力欄が空のときだけ。文字が残っているときは入力のクリアになる
Shift+Tab権限モードの切り替え（5-2）
Ctrl+Oトランスクリプトビューアの開閉。ツール呼び出しや思考を含む全履歴を遡れる（閉じるのは Esc／もう一度 Ctrl+O）
Ctrl+B実行中のタスクをバックグラウンドに送る
Ctrl+G入力中の内容を既定のテキストエディタで開く
Ctrl+Rコマンド履歴の逆順検索
Option/Alt+T拡張思考のオン・オフ
Shift+Enter改行（未対応ターミナルは /terminal-setup）
! プレフィックスシェルモード。v2.1.186 以降は出力が届くと Claude が自動で応答する（通常のプロンプトと同じ課金。旧挙動に戻すには設定 respondToBashCommands: false）
@ / #ファイル参照 / メモリへの追記

Vim モード（/config → エディタモード）、フルスクリーン描画（/tui fullscreen）、キーバインドのカスタマイズ（~/.claude/keybindings.json）も利用できます。

試してみる：キー操作を体験する

Shift+Tab（権限モード切替）、Esc 2 回（巻き戻し）、Ctrl+O（トランスクリプトを開いて Esc で閉じる）も試してください。

1-8. この章の持ち帰り

日々の生産性はこの層でほぼ決まります。覚えるキーは 3 つ、フラグは 2 つで足ります。

覚えること仕事での効き目具体的な操作
Claude Code は「LLM ＋ ツール ＋ ループ」。他の要素はすべてループに足すか、制御するか、測るもの新しい機能が出ても図 1-1 のどこかに位置づけられる。別のエージェントツールに移っても知識が持ち越せる図 1-1、3-6 の原理
Shift+Tab で権限モードを回す確認ダイアログの頻度を作業内容に合わせて即座に変えられる。日常は acceptEdits が現実的default → acceptEdits → plan
Esc は「止める」、Esc 2 回は「戻す」暴走を 1 打鍵で止められる安心感が、任せられる範囲を広げる。コンテキストは保持されるEsc / Esc ×2（＝/rewind）
Ctrl+O でトランスクリプトを読む「なぜその結論になったか」を追える唯一の手段。レビューや障害報告で根拠を示せるCtrl+O（Esc で閉じる）
ログ調査はパイプで一撃ファイルに保存して読ませる手間が要らない。障害対応の初動が速くなるtail -200 app.log | claude -p "異常があれば教えて"
調査だけさせたいときは plan で起動「勝手に直された」が起きない。設計レビュー前の調査に向くclaude --permission-mode plan
仕様で迷ったら公式を Claude 自身に読ませる全ページの機械可読な索引 llms.txt がある。二次情報の古さに悩まされない「code.claude.com/docs/llms.txt を見て◯◯の仕様を確認して」
意外と知られていない

Esc 2 回が巻き戻しになるのは、入力欄が空のときだけです。文字が残っていると入力のクリアになります。もう一つ、! のシェルモードは v2.1.186 以降出力が届くと Claude が自動で応答します。通常のプロンプトと同じ課金が発生するので、単に手元でコマンドを打ちたいだけなら設定 respondToBashCommands: false で旧挙動に戻せます。
